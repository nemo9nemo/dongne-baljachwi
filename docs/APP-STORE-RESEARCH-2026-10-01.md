# Android / iPhone 앱 조사 — 개인 장소 기록 서비스

확인일: 2026-10-01

## 1. 앞선 조사 보완

앞선 개인 중심 전환 문서는 공식 사이트·도움말 위주였으며 Google Play와 Apple App Store를 직접 대조하지 않았다. 이번에는 아래 6개 앱의 **양쪽 스토어 상세 페이지 12개**를 열어 앱 등록, 개발자, 기능 설명을 확인했다. 기존 Google 지도 목록 사례는 웹 도움말 참고로 유지하되 이 앱 조사 표와 구분한다.

앱 설치·로그인·두 운영체제에서 실제 조작은 수행하지 않았다. 스토어 스크린샷의 링크는 확인했으나 이미지 자체를 시각 분석하지 않았으므로 디자인 평가를 실화면 검증으로 보고하지 않는다. 스토어 설명은 개발자 주장이고 실제 품질 보증이 아니다. 아래의 수정 권고는 그 설명과 프로젝트 코드 분석을 결합한 판단이다.

한국 지역 URL 조회가 제한된 일부 앱은 접근 가능한 미국·네덜란드·스페인 스토어로 확인했다. 따라서 양 플랫폼 등록 확인과 한국 계정 설치 가능 여부는 구분한다. 한국 지역 설치 가능 여부는 트리플 외에는 미확인이다. 평점·다운로드·가격·순위는 지역과 시점에 따라 달라 비교 지표로 쓰지 않았다.

## 3. 앱별 비교와 프로젝트 적용

### 3.1 Swarm — 일상 방문 기록에 가장 직접적인 참고

Android와 iOS 설명 모두 빠른 장소 체크인, 사진/동행 추가, 개인 위치 기록과 지도를 소개한다. iOS 설명은 비공개 또는 공개 선택을 명시한다. 근거는 위 표의 각 스토어 상세 페이지다.

**적용:** 역 선택만으로 끝내지 않고 “어느 카페/공원인가”를 남길 수 있도록 한다. 장소·날짜와 선택 사진/메모로 빠르게 저장하고, 동행은 필수가 아니다. 재방문은 기존 장소를 다시 검색하기보다 최근 장소에서 고르게 한다.

**도입하지 않을 것:** 친구 발견·소셜 피드·주변 친구 알림·경쟁 요소. 현재의 목표는 기록과 회고다. 실제 POI 지원은 별도 단계이며 1차에는 역 + 선택 장소명으로 시작할 수 있다.

### 3.2 Day One — 개인 경험과 공유 경험의 구분

두 스토어 모두 사진/글 기반 개인 저널과 지도 회고를 소개한다. 공유 권한은 스토어 소개만으로 확정하지 않고 공식 플랫폼별 기능표를 추가 확인했다. 현행 기능표는 Android와 iOS에서 공유 저널 생성·초대·멤버 관리 등을 지원한다고 설명한다. [플랫폼별 공유 기능표](https://dayoneapp.com/guides/shared-journals/shared-journals-features-by-platform/)

공식 Android 소개에는 beta/Premium 조건의 과거 설명이 남아 있지만, 현행 가이드는 무료 공유 저널 생성과 새 플랫폼 지원 범위를 설명한다. 이 자료 차이를 “Android는 공유 불가”로 결론 내리지 않는다. 실제 설치 버전의 동작은 별도 검증 대상이다. [현행 공유 가이드](https://dayoneapp.com/guides/shared-journals/shared-journals/), [Android beta 소개](https://dayoneapp.com/shared-journals/android/)

내보내기도 플랫폼별 차이가 있다. 공식 가이드는 단일 기록의 iOS PDF 내보내기와 Android 텍스트 공유를 구분한다. 모든 플랫폼에서 단일 기록 PDF/JSON이 동일하다고 가정하지 않는다. [내보내기 가이드](https://dayoneapp.com/guides/tips-and-tutorials/exporting-entries/)

**적용:** 개인 기본 화면에서는 공유 UI를 숨기고 사용자가 만든 공유 모음 안에서만 참가자/작성자/권한을 표시한다. 새 사용자를 관계 설정 화면으로 보내지 않는다. 모음에 넣을 때 공유 대상을 명시한다.

**주의:** 앞선 프로젝트 제안인 “개인 원본을 여러 모음에 참조 연결”은 Day One 구현을 그대로 복제하는 것이 아니다. Day One은 개인 저널을 바로 공유 저널로 전환하지 않고 기록 복사/이동을 안내한다. 원본 참조·복사 중 어느 모델을 쓸지는 프로젝트 고유의 소유권 결정이다.

### 3.3 Pin Traveler — 내 장소 지도와 선택 공유

Android 설명은 장소/지역 핀, 사진, 개인 지도와 공유를 소개한다. iOS 설명은 여기에 shared trips와 함께 사진/정류장을 추가하는 협업을 명시한다. **Android 소개에 공동 편집 설명이 없다는 이유만으로 미지원이라고 판정하지 않는다.** 현재 확인한 근거만으로 양쪽의 완전한 기능 동등성은 미확인이다.

**적용:** 기록 목록과 지도는 같은 데이터를 다른 방식으로 찾는 보기다. 검색과 방문 장소 요약을 통일하고, 지도 이미지 저장은 로그인 없는 가벼운 외부 공유 방법으로 유지한다. 지도 공유와 원본 편집 초대를 구분한다.

**보류:** 여러 지도 스타일·세계 여행 통계·핀 꾸미기. 사용자의 “깔끔함”은 설정 다양성보다 기본 정보량을 줄이는 쪽으로 해석한다.

### 3.4 Journi Blog — 사진 중심 타임라인과 장소 회고

Android 설명은 사진/메모/지도, 시간·위치에 따른 사진 묶음, 개인 저널과 공동 작성, 공개 범위 선택을 명시한다. iOS 설명도 사진 타임라인·지도 탐색·개인 정보 설정과 함께 작성하는 흐름을 소개한다. 앱은 오프라인 사용을 소개하지만 Android 세부 설명에는 Premium 조건이 붙는다. 조건 없는 무료 기능으로 일반화하지 않는다.

**적용:** 사진과 짧은 글을 앞에 두고 감정·날씨·태그는 추가 정보로 접는다. 날짜는 촬영일 제안으로 입력 부담을 줄이되 자동 변경하지 않는다. 여행 모음을 만들지 않아도 일상 기록을 저장할 수 있어야 한다.

**차이:** 네이티브 앱의 오프라인 저장을 서비스워커 없는 현재 SPA가 곧바로 보장할 수는 없다. 기존 사진 캐시 스펙의 “실행 중 단절에서 열람” 범위를 유지한다.

### 3.5 Polarsteps — 개인 여행 기록에 선택적 동행

Android 스토어는 자동 경로 기록, 여행 단계별 사진/이야기, Travel Buddies 초대, 나만/팔로워/전체 공개 범위를 명시한다. iOS 소개도 여행 계획·기록·회고를 제시한다. 구체 동행 계약은 별도 공식 가이드에서 확인했다. [Travel Together](https://support.polarsteps.com/hc/en-us/articles/24266789457170-What-is-Travel-Together)

**적용:** 공유 상대는 계정의 고정 관계가 아니라 특정 모음의 참가자로 둔다. 개인 사용은 멤버십 없이 가능하게 한다. “나만 보기”가 기본이며 공개 피드 없이도 완성된 기록 경험을 제공한다.

**보류:** 자동 GPS 경로, 여행 일정 AI, 교통수단, 팔로워 네트워크. 네이티브 위치 기능과 여행 전용 구성은 현재의 일상 장소 기록 범위를 크게 늘린다.

### 3.6 트리플 — 국내 인접 사례, 직접 경쟁 앱과 구분

한국 App Store 소개는 장소 동선과 여행 일정, 동행 초대 공동 계획을 설명한다. 개인 사진 일기 중심보다 여행 준비·예약 중심이므로 핵심 디자인 기준으로 삼지 않는다.

Google Play의 조회 당시 설명에는 **11월 3일 서비스 종료 및 NOL 통합 안내**가 있다. 페이지에 노출된 업데이트 날짜는 2026-10-01이다. App Store 설명은 기존 여행 기능을 보여주므로 두 스토어 텍스트가 동일한 운영 상태를 설명한다고 가정하지 않는다. 종료 안내 문구에는 연도가 없어 날짜를 추가 추정하지 않는다. 실제 통합 진행/설치 상태는 미검증이다.

**적용:** 장소 선택 후 지도에서 동선을 확인하는 연결과, 특정 여행에만 동행을 초대하는 범위 설정을 참고한다. **제외:** 예약·쿠폰·상품 추천·채팅·가계부를 기록 앱의 기본 UI로 가져오지 않는다. 제품 전환이 있는 만큼 장기 개인 기록에는 내보내기와 데이터 보존 정책이 필요하다.

## 4. 재조사 후 수정 권고

### 유지되는 결론

1. **개인 기록을 기본으로:** 가입 후 즉시 기록. `RequireCouple`과 커플 조회 의존을 제거하는 새 개인 계약이 필요하다.
2. **공유는 모음 단위로 선택:** 계정 전체·모든 사진을 공유하지 않는다. 읽기와 공동 기여를 구분한다.
3. **빠른 방문 기록:** 장소/역·날짜·사진·짧은 메모가 기본. 감정·날씨·태그는 더 보기.
4. **정확한 장소 의미:** 역 핀과 실제 가게 핀을 구별한다. 1차는 역 + 장소명, 다음 단계는 POI/좌표.
5. **정보량 축소:** 개인 카드의 작성자와 초대 배너를 제거하고 공유 모음에서만 표시한다.

### 앞선 권고의 보정

**“기록 홈이 지도 홈보다 반드시 낫다”는 조사로 입증되지 않았다.** Swarm·Pin Traveler는 지도/장소 접근, Day One·Journi는 글/사진 회고에 강점이 있다. 초기 MVP는 최근 기록 홈을 권장하지만, 노선도 차별성을 중시하면 지도 홈도 유효하다. 같은 디자인의 기록 홈/지도 홈 두 시안에서 첫 기록 저장·과거 장소 찾기 과제를 비교한 뒤 확정한다.

“깨끗한 UI”를 작은 폰트나 기능 삭제로 해결하지 않는다. 기본 행동 하나, 선택 정보 접기, 소셜/공유 화면 분리, 중립 색상과 사진 중심 카드로 접근한다. 이번에는 스크린샷을 시각 분석하지 않았으므로 앱별 미감 순위는 매기지 않는다.

## 5. Android / iPhone에서 프로젝트가 확인할 항목

현재 프로젝트는 반응형 웹이며 이번 앱 조사가 곧 네이티브 앱 개발 결정은 아니다. Safari/iPhone과 Chrome/Android의 실제 웹 사용 검증이 먼저다.

| 영역 | 양 플랫폼 공통 완료 기준 | 특별히 확인할 차이 |
|---|---|---|
| 사진 선택 | 사진 선택·미리보기·삭제·실패 재시도 가능 | iPhone HEIC, Android 디코딩 지원, 큰 이미지 메모리 |
| 날짜 제안 | 촬영일 없거나 여러 날이면 저장 흐름을 막지 않음 | EXIF·타임존·선택 도구가 돌려주는 파일 차이 |
| 화면/키보드 | 입력 시 저장 버튼 접근, 하단 탭/대화상자 조작 | Safari viewport·safe-area, Android 뒤로가기 |
| 공유/PNG | 저장 실패 안내와 대체 방법 | Web Share 파일 지원·다운로드·사진앱 저장 방식 |
| 캐시/로그인 | 재접속·로그아웃·사용자 전환에서 데이터 경계 유지 | IndexedDB 제한·저장소 축출·복귀/bfcache |
| 지도 | 터치 이동/확대·핀 선택·목록 복귀 유지 | 지도 제스처와 페이지 스크롤 충돌 |
| 권한 | 위치 허용 없이 수동 기록 가능 | 위치/사진 권한 거부 후 복구 안내 |

네이티브 사례의 생체 잠금·백그라운드 추적·공유 시트·오프라인 편집을 웹 기능으로 그대로 약속하지 않는다. 필요한 기능이 웹에서 실제로 막힐 때 PWA 또는 네이티브 전환을 별도 검토한다.

## 6. 조사 수준 표시

이번 완료 범위: Android/iPhone 등록 대조, 앱 ID 식별, 양쪽 기능 소개 확인, 플랫폼별 도움말 보완, 국내 인접 사례와 운영 전환 확인, 프로젝트 수정 권고 갱신.

미수행 범위: 앱 설치·결제·로그인·전체 화면 조작·스크린샷 시각 QA·두 OS 간 실제 기능 동등성 테스트·한국 계정 설치 가능 여부 전체 확인. 자료 설명에 없는 기능은 “없음” 대신 “미확인”으로 표시한다.
