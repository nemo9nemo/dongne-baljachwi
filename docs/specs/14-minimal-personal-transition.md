# 개인 기록 중심 UI 전환 — 구현 범위

사용자 요청: 혼자 사용하는 기록 앱을 기본으로 하고 공유는 선택 기능으로 제공한다. 텍스트와 색을 줄여 심플하게 정리한다. 단계별 로컬 커밋과 전체 검증을 수행한다.

## 이번 단계
- 카드의 핵심 정보를 역명·날짜·기록·사진으로 정리한다. 감정·날씨·태그는 상세와 접근성 설명에 유지한다.
- 작성 화면은 역·날짜·사진·일기를 먼저 보여주고 감정·날씨·태그는 접을 수 있는 선택 항목으로 묶는다. 접어도 입력값은 유지한다.
- 태그 변경 중 이전 요청 결과와 다음 페이지가 섞이지 않도록 처리한다.
- 사진 저장 실패 상태에서도 이탈 확인을 유지하고 서버의 일기 제한 안내를 1,000자로 맞춘다.

## 2026-10-19 실행 위임에 따른 결정
- 사용자가 나머지 작업과 진행 판단을 위임했으므로 기존 권장안을 채택한다.
- 기존 공동 기록은 공동 공간에 보존한다. 작성자를 개인 소유자로 간주하거나 자동 복사하지 않는다.
- 새 기록은 기본적으로 개인 공간에 작성한다. 기존 공동 공간은 명시적으로 선택할 수 있다.
- 선택 공유는 로그인 사용자 대상 읽기 전용을 초기 계약으로 정한다. 새 공유 모음(D16)은 별도 후속 기능이며 이번 개인 공간 전환의 구현에 포함하지 않는다.
- 장소는 역 필수 + 선택 이름(최대 80자), 초대는 기존 SQL과 같은 72시간으로 맞춘다.
- 실제 개인 공간·범위 헤더·권한·서버 검색 계약은 [스펙 16](16-personal-spaces-and-search.md)을 따른다.

기존 공동 기록의 접근 권한을 화면에서만 바꾸거나 작성자를 임의의 소유자로 간주하지 않는다. 실서비스 DB 반영 및 배포는 별도 실행이 필요하다.
