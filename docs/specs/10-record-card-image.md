# 기록 카드 이미지 저장 (PNG)

> 근거: PRD §3 "기록 카드 이미지 저장 — 기록을 사진+텍스트 카드 형태 PNG로 다운로드 (P1)",
> §4 "기록 상세 — 이미지로 저장", §5.4
> 전제: `00-data-model.md`, `06-record-detail.md`

## 1. 목적 / 배경

PRD §3은 "외부 공유(P2)"를 **"이미지 저장 기능으로 일부 대체"**한다고 명시한다. 즉 이 기능은
단순 편의 기능이 아니라, **공유 요구를 흡수하는 대체재**다. 커플이 기록을 카톡으로 보내거나
인스타 스토리에 올리고 싶을 때, 서비스 링크를 공유할 수 없는(비공개 서비스) 구조에서
유일한 출구가 이미지다.

PRD §5.4가 짚은 핵심 성질: **"완전한 클라이언트 기능이라 서버 렌더링이 필요 없다."**
이 성질을 지키는 것이 이 스펙의 제약이다 — 서버 함수를 만들지 않고, 이미지를 서버에
업로드하지 않으며, 어떤 데이터도 외부로 나가지 않는다. 커플의 사적인 기록이 서버 로그나
CDN 캐시에 남지 않는다는 점에서 프라이버시상으로도 옳은 선택이다.

기술적 난제는 하나다: **Storage의 서명 URL 이미지를 canvas에 그리면 CORS 문제로 canvas가
오염(tainted)되어 `toBlob()`이 실패할 수 있다.** 이걸 해결하지 못하면 기능 자체가 성립하지
않는다 (F-05).

## 2. 사용자 시나리오

### 2.1 정상 흐름

1. 기록 상세에서 우상단 메뉴(⋯) → "이미지로 저장"을 누른다.
2. 카드 미리보기가 뜬다: 역명 / 날짜 / 감정·날씨 / 사진 / 일기 / 태그 (PRD §5.4).
3. "저장" 버튼을 누른다.
4. 잠시 생성 진행 표시 후 PNG 다운로드가 트리거된다.
5. 파일명은 `동네발자취_홍대입구_2026-08-11.png` 형태다.
6. **시트는 자동으로 닫히지 않는다.** 생성된 PNG가 미리보기 자리에 이미지로 남고,
   "저장했어요" 상태 문구와 "저장되지 않았다면 이미지를 길게 눌러 저장하세요" 안내가 함께
   표시된다 (§5·F-12·AC-11).
7. 사용자가 "닫기"(또는 Esc)를 눌러야 시트가 닫힌다.

### 2.2 예외 흐름

| 상황 | 동작 |
|---|---|
| 사진이 없는 기록 | 텍스트 전용 레이아웃으로 생성한다. 기능을 막지 않는다 |
| 사진이 5장 | 그리드로 최대 4장까지 배치하고, 초과분은 "+1" 표기 (F-08) |
| 사진 로드 실패 | 해당 사진 자리를 비우고 나머지로 생성한다. 생성 후 "사진 1장을 넣지 못했어요" 안내 |
| 사진 전부 실패 | 텍스트 전용 레이아웃으로 폴백 |
| 일기가 매우 김 (2,000자) | 카드에 들어가는 만큼만 넣고 말줄임 (F-09). 잘렸음을 미리보기에서 보여준다 |
| canvas 오염으로 내보내기 실패 | "이미지를 만들지 못했어요" + 재시도. **실패 원인이 CORS라면 재시도해도 실패하므로 §6의 대비책이 필수** |
| iOS Safari에서 `download` 미동작 | 다운로드를 시도하지 않고 결과 이미지를 시트에 띄운 뒤 "길게 눌러 저장하세요"로 안내한다 (F-12). 다운로드가 동작하는 환경에서도 결과 이미지는 동일하게 남는다 |
| 생성 중 화면 이탈 | 작업을 취소한다. 부분 파일을 남기지 않는다 |
| 오프라인 | 사진이 캐시에 없으면 로드 실패 → 텍스트 전용으로 생성 가능. 기능 자체는 동작한다 |

## 4. 데이터 모델

### 4.1 읽는 것

**신규 테이블 없음. 새 쿼리도 없다.** 기록 상세가 이미 가진 `RecordDetail`
(`06-record-detail.md` §4.1)을 그대로 입력으로 쓴다.

**카드 렌더 입력 계약**
```
CardInput {
  station_name: string
  visited_on:   date
  mood:         slug | null
  weather:      slug | null
  note:         string | null   // 전문을 받아 렌더 단계에서 자른다
  tags:         string[]
  photos:       [{ url: string, width: int, height: int }]  // 서명 URL, 최대 4장 사용
}
```

- 감정·날씨는 **슬러그로 받아 렌더 시점에 이모지/아이콘으로 변환**한다. DB에 이모지를
  저장하지 않는다는 원칙(`05` F-14)이 여기서도 유지된다.
- 이모지를 canvas에 텍스트로 그리면 OS/브라우저마다 모양이 다르고 일부 환경에서 흑백으로
  렌더된다. → §9 확인 항목.

### 4.2 쓰는 것

**없다.** DB·Storage에 어떤 쓰기도 발생하지 않는다.
생성물은 사용자의 로컬 다운로드 폴더로만 나간다.

### 4.3 RLS로 보장할 접근 범위

이 기능은 **새로운 접근 경로를 만들지 않는다.** 입력 데이터는 이미 기록 상세가 RLS를 통과해
가져온 것이다. 따라서 별도 정책이 필요 없다.

다만 두 가지를 반드시 지켜야 한다.

| 항목 | 요구 |
|---|---|
| 사진 접근 | 카드 생성 시에도 **서명 URL**만 사용한다. "canvas CORS 문제를 피하려고 버킷을 공개로 바꾸는" 해법은 **금지**한다 — 커플 격리(`00-data-model.md` D-10)가 통째로 깨진다 |
| 생성물 유출 | 생성된 PNG를 외부 서비스(이미지 호스팅, 분석 도구 등)로 전송하지 않는다. 로그에 data URL을 남기지 않는다 |

> **가장 위험한 지름길**: canvas 오염 문제를 만나면 "버킷을 public으로 바꾸면 되네"라는
> 유혹이 생긴다. 그 순간 URL만 알면 누구나 다른 커플의 사진을 볼 수 있게 된다.
> 정답은 Storage의 CORS 설정을 맞추는 것이지 접근 제어를 푸는 것이 아니다. (§6)

## 5. 상태 정의

| 상태 | 화면 |
|---|---|
| 미리보기 로딩 | 카드 자리 스켈레톤. 사진 로드를 기다린다 |
| 미리보기 정상 | 실제 출력과 동일한 비율의 카드 + "저장" / "닫기" |
| 미리보기 (사진 일부 실패) | 실패한 자리를 비우고 나머지로 구성 + "사진 N장을 불러오지 못했어요" |
| 미리보기 (사진 전부 실패) | 텍스트 전용 레이아웃 + 안내 |
| 생성 중 | 저장 버튼 스피너, 중복 클릭 차단 |
| 생성 성공 (다운로드 트리거함) | 파일 다운로드를 트리거한다. **시트는 유지한다** — 미리보기 자리를 결과 PNG 이미지로 바꾸고, 상태 문구 "이미지를 저장했어요" + 보조 안내 "저장되지 않았다면 위 이미지를 길게 눌러 저장하세요"를 함께 남긴다. 토스트는 띄우지 않는다(F-13) |
| 생성 성공 (다운로드 미지원) | 다운로드를 시도하지 않는다. **화면 구성은 위 행과 동일하고 문구만 다르다** — 상태 문구 "이미지를 만들었어요. 아래 이미지를 길게 눌러 저장하세요" + 안내 "이미지를 길게 눌러 '사진에 저장'을 선택하세요" |
| 생성 실패 | 시트 유지 + 에러 + 재시도 |
| 오프라인 | 사진 캐시가 없으면 텍스트 전용으로 생성 가능 (기능을 막지 않는다) |

**저장 성공 후 시트 유지 (2026-08-19 결정, §9 참조).** 두 "생성 성공" 행은 **같은 화면**으로
수렴한다 — 결과 이미지가 시트에 남고, 길게 눌러 저장하는 출구가 열려 있으며, **닫기 버튼 또는
Esc로만 닫힌다.** 그럼에도 두 행을 합치지 않고 구분해 둔 이유는 *동작*(다운로드 트리거 여부)과
*문구*가 다르기 때문이지, 화면 구조가 달라서가 아니다.

- 다운로드 성공 여부는 JS로 확인할 수 없다. 시트를 바로 닫으면, 브라우저가 클릭을 조용히
  무시한 환경(구형 iOS Safari, 팝업/다운로드 차단 등)에서 사용자는 **"저장된 건지 아닌지 알 수
  없는 상태"**로 남는다. 이는 AC-11의 "아무 일도 일어나지 않는 경우가 없어야 한다"를 깬다.
- 따라서 성공 경로에서도 미지원 폴백과 같은 출구(결과 이미지 + 길게 눌러 저장)를 남기고,
  **닫는 시점의 판단을 사용자에게 넘긴다.**
- 자동 닫힘이 없다는 것은 곧 여러 장을 연속 저장하거나 다시 저장을 누르는 것이 가능하다는
  뜻이다. 이는 허용한다 (AC-16의 "연타 시 1개"는 *한 번의 저장 실행* 안에서의 중복 방지다).

**부분 성공**: 사진 일부 누락 상태로 생성하는 것은 **성공으로 처리한다.** 사진 한 장이
없다고 카드 저장 자체를 막으면 사용자는 아무것도 얻지 못한다. 단 무엇이 빠졌는지는 알린다.

## 6. 비기능 요구사항

### 6.1 CORS / canvas 오염 (이 기능의 핵심 리스크)

- 사진은 crossOrigin 허용 모드로 로드해야 canvas가 오염되지 않는다.
- 이를 위해 **Supabase Storage 버킷의 CORS 설정에 배포 도메인과 로컬 개발 도메인이
  등록되어 있어야 한다.** 이건 코드가 아니라 **인프라 설정 요구사항**이며, 이 스펙의
  선행 조건이다.
- 검증 방법: 실제 서명 URL 이미지를 canvas에 그린 뒤 `toBlob()`이 성공하는지
  **구현 착수 직후 가장 먼저 확인한다.** 나중에 발견하면 레이아웃 작업이 전부 헛수고가 된다.
- 우회 대비책(순서대로): ① Storage CORS 설정 → ② 이미지를 fetch로 받아 Blob→objectURL로
  변환해 그리기 → ③ 그래도 안 되면 사진 없는 텍스트 카드로 축소.
  **버킷 공개 전환은 대비책에 포함되지 않는다.**

### 6.2 성능

- 사진 4장 포함 카드 생성 완료까지 **3초 이내** (모바일 기준).
- 생성 중 메인 스레드를 1초 이상 연속 점유하지 않는다 (UI가 얼어붙으면 실패로 보인다).
- 출력 파일 크기: 사진 포함 시 **5MB 이하**를 목표로 한다. PNG는 사진에 비효율적이라
  커질 수 있다 — 초과하면 사진 영역을 JPEG로 사전 압축해 합성한다.
  (출력 포맷 자체는 PNG 유지, PRD 명시 사항)

### 6.3 렌더 일관성

- 카드에 쓰는 폰트는 **번들에 포함된 웹폰트**여야 하고, 렌더 전에 로드 완료를 보장한다.
  시스템 폰트에 의존하면 기기마다 결과물이 달라진다.
- 한글 줄바꿈은 어절 단위로 처리한다.
- 미리보기와 실제 출력의 레이아웃이 **동일해야 한다** (배율만 다름).

### 6.4 접근성

- 미리보기 시트는 포커스 트랩 + Esc 닫기.
- 생성 진행/완료/실패를 `aria-live`로 알린다.
- 저장 후 시트에 남는 결과 이미지(F-12)에 의미 있는 대체 텍스트를 준다 — 다운로드 지원
  환경에서도 이 이미지는 남으므로 폴백 전용 요구가 아니다.
- **주의**: 생성된 PNG 자체는 접근성이 없는 산출물이다. 이 기능은 어디까지나 공유용
  보조 수단이며, 앱 내 열람(`06-record-detail.md`)이 정보 접근의 정본이다.

### 6.5 브라우저

`03-line-map.md` §6과 동일. 특히 **iOS Safari에서의 다운로드 동작을 반드시 실기로
검증**한다 (F-12 폴백의 발동 조건이 여기서 결정된다).

## 8. 완료 조건 (Acceptance Criteria)

- **AC-01** Given 사진 2장·일기·태그 3개가 있는 기록, When "이미지로 저장"을 누르면, Then 역명·날짜·감정·날씨·사진·일기·태그가 모두 포함된 카드 미리보기가 표시된다.
- **AC-02** Given 미리보기, When "저장"을 누르면, Then PNG 파일 다운로드가 트리거되고 파일명이 `동네발자취_{역명}_{YYYY-MM-DD}.png` 형식이다. **시트는 닫히지 않는다** (AC-17).
- **AC-03** Given 생성된 PNG, When 크기를 확인하면, Then 2160×2700 (4:5)이다.
- **AC-04** Given 사진이 없는 기록, When 이미지로 저장하면, Then 텍스트 전용 레이아웃으로 정상 생성된다.
- **AC-05** Given 사진 6장인 기록, When 카드를 보면, Then 4장이 그리드로 배치되고 "+2"가 표시된다.
- **AC-06** Given 일기 2,000자인 기록, When 카드를 보면, Then 일기가 말줄임되고 카드 비율은 4:5로 유지된다.
- **AC-07** Given Storage 서명 URL 사진, When 카드를 생성하면, Then canvas 오염 없이 `toBlob()`이 성공한다.
- **AC-08** Given 사진 3장 중 1장 로드 실패, When 저장하면, Then 나머지 2장으로 카드가 생성되고 누락 안내가 표시된다.
- **AC-09** Given 카드 생성 중, When 네트워크 요청을 감사하면, Then 생성 이미지를 업로드하는 요청이 존재하지 않는다.
- **AC-10** Given 카드 생성 후, When Supabase Storage를 확인하면, Then 새로 생성된 객체가 없다.
- **AC-11** Given iOS Safari, When 저장을 누르면, Then 다운로드 지원 여부와 무관하게 결과 이미지와 "길게 눌러 저장" 안내가 시트에 표시된다 — 화면에 아무 변화가 없는 경우가 없어야 한다.
- **AC-12** Given 사진 4장 포함 카드, When 저장을 누르면, Then 3초 이내에 완료되고 그동안 UI가 응답한다.
- **AC-13** Given 서로 다른 두 기기(iOS/Android), When 같은 기록으로 카드를 생성하면, Then 텍스트 줄바꿈과 레이아웃이 동일하다 (웹폰트 검증).
- **AC-14** Given 미리보기 시트가 열린 상태, When Esc를 누르면, Then 닫히고 포커스가 메뉴 버튼으로 복귀한다.
- **AC-15** Given Storage 버킷 설정, When 확인하면, Then 버킷은 여전히 **비공개**이며 이 기능을 위해 공개로 전환되지 않았다.
- **AC-16** Given 저장 버튼, When 빠르게 두 번 누르면, Then 한 번의 저장 실행으로 처리되어 파일이 1개만 생성된다.
- **AC-17** Given 다운로드가 정상 동작하는 데스크톱 브라우저, When "저장"을 눌러 파일이 떨어지면, Then 시트는 그대로 열려 있고 결과 PNG가 이미지로 표시되며 "저장되지 않았다면 위 이미지를 길게 눌러 저장하세요" 안내가 보인다. 시트는 "닫기" 또는 Esc로만 닫힌다.

## 9. 미결정 항목

> ✅ **결정 완료 (2026-08-19)**: **저장 성공 후에도 시트를 닫지 않는다.** 초안 §5는
> "생성 성공(다운로드 지원) → 토스트 + 시트 닫기"였으나, 다운로드 지원 여부와 무관하게
> **결과 이미지 + 길게 눌러 저장 안내를 시트에 남기고 사용자가 직접 닫는** 방식으로 확정했다.
> 근거: `<a download>` 클릭이 실제로 파일을 떨어뜨렸는지 JS로 알 방법이 없다(브라우저가 조용히
> 무시할 수 있다 — 구형 iOS Safari, 다운로드/팝업 차단 등). 성공을 가정하고 시트를 닫으면
> 사용자는 저장 여부를 확인할 수단이 없는 상태로 남아 **AC-11(Must)이 깨진다.** 따라서
> AC-11을 §5 초안 문구보다 우선시했고, 다운로드 미지원 폴백(F-12)과 같은 출구를 성공 경로에도
> 적용했다. 부수 결정: 완료 알림은 토스트가 아니라 시트 내 `aria-live` 상태 문구로 한다(F-13),
> 두 성공 상태는 문구만 다르고 화면 구조는 같다(§5). 반영: AC-02·AC-11 문구 조정, AC-17 신설.

> ✅ **결정 완료 (2026-08-19)**: **텍스트 라벨만 쓴다(이모지 없음).** 초안은 이모지를
> canvas에 텍스트로 그리는 방식이었으나, OS마다 모양이 다르고 일부 환경에서 흑백 렌더·
> 두부(□)가 되어 AC-13(기기 간 동일성)을 깼다. 라벨 텍스트만 쓰면 그 문제 자체가 없어진다.
> 이모지는 **범위 밖으로 미룬다** — 태그를 활용한 별도 방식으로 추후 추가 예정이며, 이번
> 스펙의 F-02(카드 포함 항목: 감정·날씨)는 텍스트 라벨로 계속 충족된다.

> ❓ **카드 비율 4:5 / 해상도 2160×2700**은 임의로 정한 값이다. 주 공유 채널이 카카오톡인지
> 인스타그램인지에 따라 최적 비율이 다르다.

> ❓ **워터마크 문구와 서비스명**. PRD §1은 서비스명이 "동네 발자취 (가칭, 변경 가능)"이라고
> 명시한다. 파일명(F-11)에도 서비스명이 들어가므로, 이름이 확정되면 두 곳을 함께 바꿔야 한다.

> ❓ **사진 5장 이상일 때 "+N" 표기**가 필요한지, 그냥 4장만 보여주고 말지.

> ❓ **일기 말줄임 길이**. 카드 레이아웃 확정 전에는 정할 수 없다. 디자이너 작업 후 확정.

> ❓ **Supabase Storage CORS 설정 상태 미확인.** `.env.local`이 없어 실제 프로젝트에
> 접근하지 못했다. §6.1의 검증을 구현 착수 직후 수행해야 하며, 실패 시 이 기능의
> 사진 포함 여부가 통째로 흔들린다.
