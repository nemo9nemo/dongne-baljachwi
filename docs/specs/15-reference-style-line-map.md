## 1. 목표와 적용 범위

**밝은 바탕, 정돈된 8방향 노선, 넓은 도심 순환부, 연결된 환승 표시, 선을 피해 배치한 역명으로 첨부 이미지와 유사한 노선도를 만든다.** 방문 기록·노선 필터·역 상세 이동은 이 도식 위에서 동작한다.

사용자의 ‘출력’은 우선 앱 화면에 표시하는 것으로 해석했다. 인쇄·이미지 파일 내보내기는 별도 후순위다. 후속 요청에 따라 **노선도를 제품의 메인·첫 화면으로 유지하고 가장 먼저 개선**한다. 최근 기록 중심 홈으로 대체하지 않는다.

스펙 03의 기존 정적 자산·역 코드 조인·뷰포트 복원 원칙은 유지한다. 다음 개선 구현에서는 본 문서의 라벨·줌·환승·선택·도식 저작 기준을 적용한다. 현재 코드와 달라지는 부분은 구현 완료로 취급하지 않는다.

## 3. 권장 구현 방식

**기존 SVG 렌더러 + 검증된 연결 데이터 + 별도로 저작하는 도식 좌표/라벨**을 기본안으로 한다. 현재 팬·줌과 방문 집계 연동은 재사용하되 표시 규칙을 개선한다.

먼저 [공식 PDF/JPG 제공 자료](https://data.seoul.go.kr/dataList/OA-22535/F/1/datasetView.do)의 원본을 검사한다. 편집 가능한 벡터이고 코드 매핑 비용이 합리적이면 이를 저작 출발점으로 활용한다. 그렇지 않으면 독립된 벡터 도식을 제작한다. 제공 파일·이용 조건은 참고 문서 §4를 따른다.

### 3.1 제작 순서

1. **연결 관계 확정**: 지원 역 목록, 각 노선의 실제 순서, 순환·지선·공유 구간, 환승역 그룹을 준비한다. 도식의 모양으로 열차 연결을 추정하지 않는다.
2. **전체 구도 설계**: 2호선 순환부와 주요 환승역·한강을 먼저 놓고, 도심 내부에 라벨 공간을 확보한다. 외곽은 간격을 압축하되 순서와 분기는 유지한다.
3. **선 저작**: 선을 수평·수직·대각선으로 만들고 필요하면 역 사이에 꺾임점을 추가한다. 평행 노선은 일정한 간격으로 분리한다. 단순 교차를 환승으로 표시하지 않는다.
4. **역·라벨 배치**: 심볼, 연결 환승 표시, 이름, 종점 배지의 충돌을 함께 조정한다. 대표 밀집 구간을 먼저 완성한 뒤 전역으로 확장한다.
5. **코드 매핑·정적 산출**: 물리 역의 `stationCode`, DB의 `lineCode`를 유지한다. 제작 원본→버전 관리 데이터→SVG 출력 경로를 둔다.
6. **재생성 보장**: 수작업 보정값을 별도 저작 데이터/override로 보관한다. 생성 스크립트 재실행으로 확정된 배치를 덮어쓰지 않는다.

도식 좌표는 위경도와 다른 좌표계다. 배경 이미지를 채택해도 위경도에 단일 축척을 곱해 역 마커를 맞출 수 없다. 같은 도식 좌표계로 모든 역을 매핑하고 변환을 공유해야 한다.

### 3.2 화면 레이어

| 아래 → 위 | 내용 | 동작 |
|---|---|---|
| 배경 | 밝은 바탕, 옅은 한강·권역 윤곽 | 역이나 선보다 낮은 시각적 강조. 실제 지리 위치 안내와 구별 |
| 노선 | 경로, 공유/평행 구간, 종점 번호 | 필터는 소속 노선별 적용 |
| 역·환승 | 일반역 원, 노선별 환승 표시와 연결 외곽선 | 하나의 물리 역에 하나의 방문 집계·상세 목적지 |
| 기록 상태 | 방문 장식, 선택 테두리, 상세 배율의 횟수 | 원래 노선색과 환승 정보를 가리지 않음 |
| 역명 | 배율별 선택 라벨, 역별 보정 위치 | 선택·검색 역은 우선 표시, 충돌 시 주변 일반 라벨 조정 |
| 고정 UI | 검색, 호선 선택, 범례, 확대/축소, 전체 보기 | 지도 좌표 변환 밖에 배치 |

### 3.3 정적 데이터 v2와 후속 확장

1차 v2는 `schemaVersion/revision/source/viewBox`, 경로별 `id/lineCode/stationCodes/closed/polyline`, 역별 `stationCode/x/y/labelAnchor/labelPriority/labelOffset/labelLines`를 사용한다. 동일 `lineCode`에 여러 경로를 허용하며 꺾임점 수와 역 수는 독립적이다. 아래 표에는 이후 저작 도구·표시 그룹·환승 그룹 확장을 포함한다.

| 데이터 | 필요한 필드·역할 |
|---|---|
| 문서 메타 | `schemaVersion`, 도식 버전, 역 마스터 기준 버전, 지원 범위, 원본 출처·파일 기준일·이용 조건, `viewBox` |
| 노선 표시 그룹 | 사용자용 노선명/번호/색과 실제 `lineCode` 목록. 본선·지선의 표시 그룹을 명시 |
| 연결 그래프 | 물리 역 코드, 구간의 양 끝 역, 소속 노선, 실제 역 순서, 분기·순환 관계 |
| 선 도형 | 구간 ID, `lineCode`, 경로 점 목록. **점 개수와 역 개수의 일치 조건 제거**, 역 사이 꺾임 허용 |
| 역 배치 | `stationCode`, 기준 `x/y`, 소속 노선 집합. 연결 그래프와 매핑 검증 |
| 환승 표시 | 물리 역에 속한 노선별 표시 위치와 연결 도형. 여러 시각 요소를 하나의 선택/방문 대상으로 묶음 |
| 라벨 | 앵커, `dx/dy`, 정렬, 명시적 줄바꿈, 중요도, 노출 단계. 역 이름 자체의 정본은 마스터 |
| 배경 | 한강 등 도식 경로. 지리 좌표와 혼합하지 않음 |

필터와 환승 심볼은 `lineCodesByStationCode`의 다대다 소속을 사용한다. 1차 사용자용 노선 그룹은 마스터 `color_token`을 기준으로 묶고 가장 작은 `sort_order`로 정렬한다. 같은 토큰의 독립 서비스가 추가되면 명시적 표시 그룹으로 분리해야 한다. 그림 편집 도구의 임의 ID를 DB 역 ID로 간주하지 않는다.

## 4. UI·상호작용 기준

### 4.1 전체 보기와 상세 보기

- 처음 노선도에 들어왔을 때는 **전체 도식 윤곽**을 보여준다. 기존 세션의 유효한 뷰포트가 있으면 복원을 우선한다. 최근 방문 지역으로 자동 이동하는 것은 기본값으로 채택하지 않는다.
- 전체 보기에는 주요 환승역·종점·노선 번호를 우선 표시한다. 모든 역명을 작은 글씨로 밀어 넣지 않는다. ‘확대하거나 역을 검색해 보세요’ 안내와 전체 보기 버튼을 제공한다.
- 확대하면 일반 역명을 단계적으로 추가한다. 상세 탐색 시 역명 **12–14 CSS px 이상을 설계 목표**로 하고, 선택 역과 검색 결과는 항상 읽을 수 있게 표시한다. 크기만 키워 라벨이 겹치면 배치/표시 우선순위도 조정한다.
- 데스크톱은 지도 영역을 넓히고 정보 패널을 옆에 둘 수 있게 한다. 지도까지 480px 프레임에 묶는 현 구조를 개선한다.

### 4.2 줌·터치·라벨

`s_fit = min(캔버스 폭 / 도식 폭, 캔버스 높이 / 도식 높이)`, `s = s_fit × k`를 기준으로 설계한다. 화면 글자 크기와 역 간격이 만족되는 `s_detail`에 도달하도록 `k_max ≥ s_detail / s_fit`을 보장한다. **줌 상한 8을 다른 고정 숫자로만 바꾸는 처방은 충분하지 않다.**

선과 지형은 공통 변환으로 확대한다. 글자·선택 영역은 화면상 읽히는 크기 범위를 유지하도록 설계한다. SVG의 선 두께 고정만으로 글자 크기가 해결되지는 않는다. 팬 중 모든 라벨을 재배치하지 않고, 뷰포트/표시 단계 변경 때 충돌 결과를 갱신한다.

터치 기준은 최소 44×44 CSS px를 목표로 하되 밀집 구간에서 영역이 중첩될 수 있음을 인정한다. 모호한 탭은 주변으로 확대하고, 이미 상세 배율인데도 모호하면 역 이름 후보를 제시한다. 가장 가까운 역으로 조용히 이동시키는 동작은 대체한다. 유일한 역 선택은 기존처럼 상세로 바로 이동한다.

### 4.3 환승·방문·필터

- 환승역은 소속 노선색의 작은 원/마크를 연결한 심볼로 표현한다. 선이 단순히 교차하는 곳과 구별한다.
- 방문은 작은 체크/스탬프 장식 등으로 별도 표시하고, 정확한 횟수는 선택/상세 배율에서 보여준다. 6단계 채움 농도를 외우게 하는 표현은 보조 정보로 축소한다. 스펙 03의 기존 농도 정책을 대체하는 제안이다.
- 선택 노선이 환승역 소속 중 하나이면 해당 역을 강조한다. 환승 가능한 다른 노선의 존재도 심볼에서 읽을 수 있어야 한다.
- 노선색 외에 번호/이름, 방문/미방문/환승/선택의 간단한 범례를 제공한다. 모바일에서는 접힌 도움말로 열 수 있다.
- 방문 집계 로딩·실패를 미방문 확정으로 표시하지 않는다. ‘방문 정보 확인 중/불러오기 실패’를 별도로 안내한다.

### 4.4 검색·키보드 접근

헤더에서 역명·초성으로 검색한다. 결과의 기본 동작은 **역 상세 열기**로 유지하고, 별도 ‘노선도에서 보기’를 제공해 해당 역에 확대·초점 이동할 수 있게 한다. 도식에 없는 역은 상세 접근을 유지하며 지도 보기 동작의 불가 사유를 설명한다.

646개 역을 순서대로 Tab 이동해야만 찾는 구조를 대체한다. 검색 목록으로 모든 역에 접근하고, 지도 포커스는 선택/가시 역 중심으로 관리한다. 노선 필터·줌·전체 보기 버튼에도 키보드 이름과 조작을 제공한다.

### 4.5 내보내기 확장

앱 화면 표시가 안정화된 뒤 **현재 영역 PNG**와 **전체 도식 SVG/PDF**를 검토한다. 현재 영역은 화면 상태를 반영하고, 전체 출력은 별도의 큰 캔버스·라벨 조판·범례·출처·기준일을 사용한다. 화면에서 생략한 라벨이 인쇄본에서도 빠지거나 잘리지 않도록 별도 검수한다. 기록 본문·사진 등 개인정보의 포함은 기본 노선도 출력과 분리한다. 기존 기록 카드 PNG 기능과도 별개다.

## 5. 우선순위와 권장 순서

아래 LM 항목은 백로그 M01–M08을 실행 가능한 작업으로 나눈 것이다. 전체 백로그 33개에 중복 가산하지 않는다. 이 표의 P0는 노선도 개선 착수의 선결 조건이며, 전체 제품의 저장 안정성 P0보다 일괄 우선한다는 뜻은 아니다.

| ID | 우선순위 | 작업 | 산출물 / 완료 기준 | 연결 |
|---|---|---|---|---|
| LM-01 | **P0** | 현재 라벨·줌 결함 해소 기준 확정 | 360/390/480px에서 읽을 수 있는 상세 단계에 도달. 전체 보기와 복원 동작 유지 | M01 |
| LM-02 | **P0 · 제작 선결** | 원본 적합성·지원 범위·연결 관계 검증 | 공식 PDF/JPG의 실제 구조와 조건 기록, 현 역 마스터와 차이 목록, 성수·신도림 분기 접합 확인 | M05, M08 |
| LM-03 | **P1 · 먼저** | 도식 v2와 도심 파일럿 저작 | 2호선 순환부, 성수/신정지선, 홍대입구·서울역·왕십리·고속터미널 등 연결 노선 포함. 꺾임점/환승/라벨 분리 검증 | M02, M05 |
| LM-04 | **P1** | 전체 지원 범위로 배치 확장 | 현재 지원 역 누락 없이 표현. 범위 밖·준비 중 역은 검색에서 접근. 재생성해도 보정 보존 | M05, M08 |
| LM-05 | **P1** | 검색·명확한 탭·필터·범례 | 초성 검색, 지도에서 보기, 다중 소속 환승 강조, 모호한 선택 처리, 상태 의미 전달 | M02, M03, M06, M07 |
| LM-06 | **P1** | 화면 크기 대응과 회귀 확인 | 모바일 밀집 구간 검수, 데스크톱 넓은 배치, 복원·키보드·팬/줌 성능 확인 | M04, E02 |
| LM-07 | **P2** | 큰 글씨/고대비·파일 출력 | 화면 모드 및 출력물 별도 조판·출처·역명 잘림 검수 | M06 및 확장 |

권장 흐름: **LM-01의 가독성 확보와 LM-02 조사 → LM-03 파일럿 → LM-04 전체 확장 및 LM-05 탐색 → LM-06 통합 검수 → LM-07**. 파일럿은 구현 검증 범위이며 최종 제품의 지원 역 축소를 뜻하지 않는다.

## 6. 완료 기준

| 검증 영역 | 완료 조건 |
|---|---|
| 레퍼런스 적합성 | 전체 보기에서 정돈된 8방향 선, 넓은 도심, 낮은 강조의 한강, 연결 환승 심볼, 종점 배지를 첨부 이미지와 나란히 비교. 색상만 바꾼 결과로 완료 처리하지 않음 |
| 연결 정합성 | 모든 표시 역 코드가 마스터에 존재. 노선 순서·분기·순환을 그래프와 대조. 성수·신도림 분기 연결, 공유 구간, 단순 교차의 비환승 구분 확인 |
| 환승 상태 | 홍대입구 등 다중 노선 역에서 소속 노선을 각각 선택해도 방문/선택 상태 유지. 시각 마크 수와 무관하게 집계·기록 대상은 물리 역 1개 |
| 모바일 | 360×800, 390×844, 480×900의 전체 보기·상세 보기·노선 필터 화면 검수. 상세 역명 목표 크기 충족, 라벨/심볼 충돌 해소, 모호한 탭의 잘못된 즉시 이동 없음 |
| 데스크톱 | 1280×800에서 지도 공간 확대, 휠·드래그·검색 조작 가능. 사이드 패널이 선택 역을 가리지 않음 |
| 정보 계층 | 전체 보기 주요 역/종점 라벨, 상세 보기 일반역 라벨, 선택역 우선 표시. 이름 중간의 무의미한 분할이나 잘림 없음 |
| 기록 상태 | 0회·1회·2회 이상·99+·집계 로딩·실패를 구분. 방문 장식이 환승 노선색을 덮지 않음 |
| 탐색·접근성 | 초성/이름 검색으로 임의 역 상세 접근. 지도에서 보기로 역 초점 이동. 키보드만으로 검색·필터·확대·전체 보기 수행 |
| 복원 | 역 상세/지도 모드 왕복 후 같은 필터의 위치·배율 복원. 필터 변경 시 기존 복원 우선순위 준수 |
| 생성·유지보수 | 동일 입력과 보정값에서 동일 산출. 신규역 추가 시 기존 보정 보존. 도식 버전·출처·기준일 추적 |
| 성능 | 대표 모바일·데스크톱에서 팬/줌과 초기 로드를 측정. 스펙 03의 목표(60fps, 초기 2.5초)를 실제 장치·네트워크 조건과 함께 보고. 달성한 것으로 미리 기재하지 않음 |

현재 좌표 데이터의 정확한 역 수·노선 항목 수는 검토 시점의 값이다. 신규 개통·마스터 변경 시 고정 숫자를 테스트의 정답으로 유지하지 말고 지원 범위를 기준으로 검증한다.
