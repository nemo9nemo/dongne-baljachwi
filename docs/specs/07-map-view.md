# 지도 보기 (노선도 ↔ 지도 전환)

> 근거: PRD §4 "지도 보기 — 노선도 헤더의 토글로 전환. 기록이 있는 장소만 좌표 기반으로
> 핀 표시", §3 "지도 보기 전환 (P1)", ADR-001(카카오맵 확정)
> 전제: `00-data-model.md`, `02-station-master.md`, `03-line-map.md`

## 1. 목적 / 배경

노선도는 도식이다. 실제 거리와 방향이 왜곡되어 있어서 "우리가 주로 어느 동네에서 노는가",
"이 두 역이 실제로 가까운가"를 알 수 없다. 지도 보기는 **같은 데이터를 실제 지리 위에
다시 보여주는 보조 뷰**다.

PRD가 P1로 두고 "노선도 헤더의 토글"로 정의한 점이 중요하다. 이건 독립 화면이 아니라
**노선도의 다른 표현**이다. 따라서 두 뷰는 같은 데이터·같은 진입점(역 탭 → 역 상세)을
공유해야 하고, 서로 다른 세계처럼 보이면 안 된다.

핵심 결정 사항: **핀은 "기록이 있는 역"만 찍는다.** 전 역을 찍으면 지도가 지하철 노선도와
같아지고(그럴 거면 노선도를 보면 된다), 핀 개수도 700개가 되어 의미를 잃는다.

## 2. 사용자 시나리오

### 2.1 정상 흐름

1. 노선도 화면 헤더의 토글에서 "지도"를 누른다.
2. 카카오맵이 뜨고, **기록이 있는 역에만 핀**이 찍힌다.
3. 초기 뷰는 모든 핀이 들어오도록 맞춰진다. (같은 세션에서 이미 지도를 보다 나갔던 경우라면
   그때의 중심·레벨이 대신 복원된다 — F-12)
4. 축소하면 가까운 핀들이 클러스터로 묶여 개수가 표시된다.
5. 핀을 탭하면 역명·방문 횟수·마지막 방문일이 작은 정보창으로 뜬다.
6. 정보창을 탭하면 역 상세로 이동한다 (`04-station-detail.md`).
7. 토글을 다시 누르면 노선도로 돌아간다. **노선도의 직전 뷰포트가 유지된다.**

### 2.2 예외 흐름

| 상황 | 동작 |
|---|---|
| 기록 0건 | 지도는 뜨지만 핀이 없다. 서울 중심 기본 뷰 + "기록을 남기면 여기에 표시돼요" 안내. 노선도로 돌아가는 버튼 강조 |
| 카카오맵 SDK 로드 실패 | 지도를 포기하고 **노선도로 자동 복귀** + 토스트 "지도를 불러오지 못했어요". 빈 회색 화면을 남기지 않는다 |
| 카카오맵 도메인 미등록/키 오류 | 위와 동일 처리. 콘솔에는 원인을 남긴다 |
| 방문 집계 로드 실패 | 지도는 뜨되 핀 없음 + 재시도 배너 |
| 좌표가 없는 역에 기록이 있음 | 핀을 찍지 않는다. 대신 "지도에 표시할 수 없는 기록 N건" 안내 (기록이 사라져 보이면 안 됨) |
| 브라우저 새로고침 | 보던 뷰 종류(노선도/지도)는 URL로 유지된다(F-11). **뷰포트는 노선도·지도 양쪽 모두 초기 상태로 리셋된다**(F-12 — 보존은 SPA 세션 내 전환에만 적용) |
| 화면에 핀이 하나도 안 보임 (멀리 팬했거나, 그 상태가 F-12로 복원됨) | 자동으로 되돌리지 않는다. 사용자가 **"전체 핀 보기"(F-17)** 를 눌러 전체 핀 bounds로 복귀한다 |
| 오프라인 | 카카오맵 타일을 못 받는다. 지도 전환을 막고 사유 표시 |
| 커플 미연결 | 이 화면에 도달하지 않는다 |

## 3. 기능 요구사항

| ID | 요구사항 | 우선순위 | 비고 |
|----|---------|---------|------|
| F-01 | 노선도 헤더의 토글로 전환한다. 별도 하단 탭을 만들지 않는다 | Must | PRD §4. 하단 탭은 노선도/타임라인/프로필 3개 고정 |
| F-02 | **기록이 있는 역에만** 핀을 표시한다 | Must | PRD §4 "기록이 있는 장소만" |
| F-03 | 핀 위치는 `stations.lat/lng` (그룹 대표 좌표) | Must | `02` F-07 |
| F-04 | 핀에 방문 횟수를 표시한다 | Should | 노선도 뱃지와 정보 일관성 |
| F-05 | 핀 탭 → 정보창(역명·방문 N회·마지막 방문일) → 탭 시 역 상세 이동 | Must | 핀 탭 즉시 화면 이동은 오탭 시 손실이 크다 |
| F-06 | 초기 뷰포트는 전체 핀의 bounds에 맞춘다. 핀 1개면 적정 배율로 센터링. **단 F-12의 복원이 적용된 진입에서는 이 자동 맞춤을 생략한다 (F-12 > F-06)** | Must | 2026-08-21 우선순위 확정(§9). 복원해 놓고 곧바로 전체 핀 bounds로 덮으면 복원이 무의미하다. 핀 목록이 그 사이 바뀌어 복원 뷰포트에 핀이 안 보이더라도 자동으로 되돌리지 않는다 — 되돌리는 것은 사용자가 F-17로 명시적으로 한다 |
| F-07 | 기록 0건이면 서울시청 중심 기본 뷰 | Must | 좌표 없는 상태의 폴백. **F-12의 복원분이 있으면 복원이 우선한다**(빈 상태 안내 카드는 그대로 표시) |
| F-08 | 핀이 겹칠 때 클러스터링한다 | Must | F-09 참조 |
| F-09 | 클러스터링 임계: 지도 축소 레벨이 일정 이상일 때 활성. 클러스터 탭 시 그 범위로 확대 | Must | 구체 레벨값은 §9 미결정 |
| F-10 | 팬/줌/더블탭 등 기본 지도 조작을 지원한다 | Must | 카카오맵 기본 동작 |
| F-11 | 토글 상태(노선도/지도)를 URL에 반영한다 | Should | 새로고침 시 유지되는 것은 **뷰 종류뿐**이다. 뷰포트는 F-12 범위 밖 |
| F-12 | 노선도 ↔ 지도를 오갈 때 **각 뷰의 직전 뷰포트를 각각 복원한다**(노선도는 중심·배율, 지도는 중심·확대 레벨). 두 뷰의 뷰포트는 **독립적으로** 기억한다(좌표계가 다르므로 변환하지 않는다). 복원 조건이 성립한 진입에서는 **F-06·F-07의 초기 뷰포트 맞춤보다 복원이 우선**한다. 보존 범위는 SPA 세션 내 화면 전환까지이며 **브라우저 새로고침·새 탭에는 적용하지 않는다** | Must | 2026-08-21 우선순위·범위 확정(§9). 노선도 쪽 조건(호선 필터 일치 시에만 복원)은 `03` F-21·F-21a가 정의한다. 지도에는 호선 필터가 없으므로(F-13) 그 조건이 없다 |
| F-13 | 호선 필터는 지도 보기에 **적용하지 않는다** | Must | 지도에는 노선 선이 없어 "흐림 처리" 대상이 없다. 필터 UI는 지도에서 숨긴다 |
| F-13a | 필터 UI가 숨겨져도 헤더 영역의 높이는 노선도/지도 양쪽에서 동일하게 유지한다 | Must | 2026-08-25 결정(§9). 토글 직후 레이아웃 점프 방지 — 구체 구현(자리 비우기 vs 높이 고정)은 개발자 몫 |
| F-14 | 카카오맵 SDK는 지도 보기로 전환할 때 **지연 로드**한다 | Must | P1 보조 기능이 기본 화면(노선도)의 초기 로드를 무겁게 만들면 안 된다 |
| F-15 | 현재 위치 표시는 제공하지 않는다 | Must | 위치 권한을 요구할 만한 사용 목적이 없다 (기록은 과거의 장소다) |
| F-16 | 지도 위에 노선 선을 그리지 않는다 | Must | 노선도와 역할을 나눈 취지. 지도는 "실제 위치"만 답한다 |
| F-17 | **"전체 핀 보기" 리셋 컨트롤**을 지도 위에 둔다. 누르면 뷰포트를 F-06의 초기 상태(전체 핀 bounds, 핀 1개면 단일 핀 배율 센터링)로 되돌린다 | Must | 2026-08-21 결정(§9). `03` F-22("전체 보기로 리셋")의 지도 대응물. 지도는 팬 범위 제한이 없어(`03` F-19 같은 제약이 없다) 노선도보다 길을 잃기 쉬우므로 우선순위를 Should가 아닌 Must로 둔다 |
| F-17a | 노출 조건: **지도 렌더가 완료(`sdkState=ready`)되고 핀이 1개 이상일 때 항상 노출**한다. "현재 뷰포트가 핀을 담고 있는지"를 판정해 조건부로 노출하지 **않는다** | Must | 조건부 노출은 팬 중 버튼이 나타났다 사라져 산만하고, 길을 잃은 뒤에야 처음 보이는 컨트롤은 사용자가 존재를 학습하지 못한다. 판정 비용(팬/줌마다 bounds 포함 검사)도 얻는 것에 비해 크다 |
| F-17b | 핀 0건(빈 상태)에서는 F-17을 **표시하지 않는다** | Must | 되돌아갈 핀이 없다. 빈 상태의 탈출구는 §5의 안내 카드와 "노선도로 가기"다 |
| F-17c | 리셋으로 만들어진 뷰포트도 F-12의 보존 대상이다. 리셋 후 노선도에 갔다 돌아오면 **리셋된 뷰포트**가 복원된다 | Must | 리셋을 "일시적 미리보기"가 아니라 사용자가 선택한 현재 화면 상태로 취급한다 |
| F-17d | 리셋 시 열려 있던 핀 정보창(F-05)은 닫지 않는다 | Should | 정보창은 핀 좌표에 고정된 오버레이라 뷰포트가 바뀌어도 가리키는 대상이 그대로다. 닫으면 오히려 사용자가 잃는 것이 생긴다 |
| F-17e | 접근 가능한 이름은 **"전체 핀 보기"** 로 고정한다. 시각 표현(아이콘/텍스트)과 정확한 배치는 디자이너가 정하되, **노선도의 `03` F-22 버튼과 같은 계열의 심볼·같은 화면 모서리**를 쓴다 | Must | §1 "두 뷰가 서로 다른 세계처럼 보이면 안 된다". 토글로 오갈 때 같은 기능의 버튼이 다른 자리에 있으면 안 된다. 카카오맵 기본 컨트롤과 겹치지 않아야 한다 |
| F-17f | 키보드로 포커스·실행 가능한 실제 버튼 요소여야 한다 | Must | §6은 "지도 자체"를 스크린리더 조작 대상에서 제외했을 뿐, 지도 위의 DOM 컨트롤은 예외가 아니다 |

## 4. 데이터 모델

### 4.1 읽는 것

**신규 테이블 없음. `03-line-map.md`와 완전히 같은 데이터를 읽는다.**

| 출처 | 내용 |
|---|---|
| 마스터 캐시 (`stations`) | `id`, `name`, `lat`, `lng` |
| `couple_station_visits` 뷰 | `station_id`, `visit_count`, `last_visited_on` |

**핀 목록 파생 규칙**
```
pins = couple_station_visits
         .map(v => join stations by station_id)
         .filter(s => s.lat != null && s.lng != null)
```

- **별도 쿼리를 추가하지 않는다.** 노선도에서 이미 받은 방문 집계를 그대로 쓴다.
  토글 전환 시 네트워크 요청 0회가 목표다 (F-14의 SDK 로드 제외).
- 좌표가 없는 역은 `02` §3 F-02에 따라 `is_active=false`로 적재되므로 사실상 드물지만,
  방어적으로 필터한다.

### 4.2 쓰는 것

**없다.** 읽기 전용 뷰다.

### 4.3 RLS로 보장할 접근 범위

| 대상 | 범위 |
|---|---|
| `couple_station_visits` | `couple_id = current_couple_id()` (뷰 `security_invoker = true`) — **이 화면의 유일한 격리 대상** |
| `stations` | 로그인 사용자 전원 읽기 |

> 이 화면이 노출하는 민감 정보는 **"이 커플의 활동 반경"**이다. 핀 분포만 봐도 생활권이
> 드러난다. 따라서 방문 집계 뷰의 `security_invoker` 설정이 빠지면 노선도보다 더 직접적인
> 프라이버시 사고가 된다.
>
> 추가로 **카카오맵 SDK는 외부 스크립트**다. 핀 좌표는 브라우저 내에서만 사용하고,
> 카카오 API로 커플의 방문 좌표 목록을 전송하는 호출(장소 검색, 주소 변환 등)은 하지 않는다.
> 지도 타일과 렌더링만 사용한다.

### 4.4 카카오맵 키 취급

- 브라우저 JavaScript 키(`VITE_KAKAO_MAP_APP_KEY`)를 사용한다. 이 키는 번들에 노출된다.
- 노출 자체는 정상이며, **보호는 카카오 개발자 콘솔의 플랫폼(웹) 도메인 등록으로** 한다.
  배포 도메인과 로컬 개발 도메인을 모두 등록해야 한다.
- 키 미등록 도메인에서는 SDK가 실패하므로 §2.2의 폴백이 반드시 동작해야 한다.

## 5. 상태 정의

| 상태 | 화면 |
|---|---|
| SDK 로딩 중 | 지도 영역 스켈레톤 + 헤더/토글은 그대로 동작 (되돌아갈 수 있어야 한다) |
| SDK 로드 실패 | 노선도로 자동 복귀 + 토스트. 토글은 지도 쪽이 비활성 표시 |
| 지도 렌더 완료·핀 계산 중 | 지도는 보이고 핀만 잠깐 없음. 로딩 인디케이터를 지도 위에 띄우지 않는다. 핀이 아직 0개이므로 "전체 핀 보기" 버튼도 아직 없다 — 핀이 도착하면 나타난다 |
| 정상 | 핀/클러스터 표시 + "전체 핀 보기" 버튼 상시 노출 (F-17·F-17a) |
| 빈 상태 (기록 0건) | 서울 중심 뷰 + 안내 카드 "기록을 남기면 여기에 표시돼요" + 노선도로 가기. **"전체 핀 보기" 버튼은 없다** (F-17b) |
| 방문 집계 실패 | 지도 정상 + 상단 배너 "방문 정보를 불러오지 못했어요" + 재시도 |
| 좌표 없는 기록 존재 | 하단에 "지도에 표시할 수 없는 기록 N건" (탭 시 해당 역 목록) |
| 오프라인 | 토글의 지도 항목 비활성 + 사유. 이미 지도에 있었다면 노선도로 복귀 |

**부분 성공**: 지도는 뜨지만 일부 핀의 좌표가 없는 경우 — 나머지 핀은 정상 표시하고
누락 건수를 알린다. 조용히 빠뜨리지 않는다.

## 6. 비기능 요구사항

- **핀 규모**: 커플당 방문 역은 현실적으로 수십~수백 개다. 상한을 수도권 전 역(약 700)으로
  잡아도 클러스터링으로 감당된다. **전국 확장(1,100역)에서도 같은 설계가 성립한다.**
- **전환 속도**: 노선도 → 지도 전환 시 (SDK 캐시된 상태에서) 500ms 이내 첫 렌더.
- **SDK 로드**: 지연 로드(F-14). 노선도 초기 번들에 카카오맵 스크립트가 포함되면 안 된다.
- **조작 성능**: 핀 300개 상태에서 팬/줌 시 눈에 띄는 끊김이 없어야 한다.
- **접근성**:
  - 지도는 근본적으로 시각적 매체다. **동일 정보에 도달하는 대체 경로가 이미 존재한다**
    (역 상세, 타임라인). 지도 자체를 스크린리더로 조작 가능하게 만들려 하지 않는다.
  - 대신 토글 버튼은 현재 상태를 명확히 알리고(`aria-pressed` 등), 지도 영역에는
    "기록이 있는 역 N곳이 지도에 표시됨. 목록으로 보려면 타임라인을 이용하세요"라는
    텍스트 대안을 둔다.
  - 토글은 키보드로 조작 가능해야 한다.
- **브라우저**: `03-line-map.md` §6과 동일. 카카오맵 SDK의 지원 범위를 따른다.

## 8. 완료 조건 (Acceptance Criteria)

- **AC-01** Given 기록이 있는 역 5곳, When 지도 보기로 전환하면, Then 핀이 정확히 5개 표시되고 모든 핀이 화면에 들어온다.
- **AC-02** Given 기록이 없는 역, When 지도를 보면, Then 그 역에는 핀이 없다.
- **AC-03** Given 홍대입구 방문 3회, When 핀을 탭하면, Then 정보창에 "홍대입구 · 3회 · 마지막 방문일"이 표시된다.
- **AC-04** Given 정보창이 열린 상태, When 정보창을 탭하면, Then 해당 역 상세로 이동한다.
- **AC-05** Given 핀이 밀집한 지역, When 축소하면, Then 클러스터로 묶이고 개수가 표시되며 탭 시 확대된다.
- **AC-06** Given 노선도를 확대·이동한 상태(**호선 필터는 그대로**), When 지도로 갔다가 노선도로 돌아오면, Then 노선도의 직전 뷰포트가 복원된다. (**2026-08-21 개정**: 보존 범위는 SPA 세션 내 전환. 새로고침은 대상이 아니다 — AC-17)
- **AC-07** Given 지도 보기 상태, When 화면을 새로고침하면, Then 지도 보기가 유지된다 (F-11). **유지되는 것은 뷰 종류뿐이고 지도 뷰포트는 초기화된다 — AC-17.**
- **AC-08** Given 기록 0건, When 지도로 전환하면, Then 핀 없이 기본 뷰와 안내 문구가 표시된다.
- **AC-09** Given 카카오맵 SDK 로드를 실패시킨 상태, When 지도로 전환하면, Then 노선도로 자동 복귀하고 토스트가 뜬다 (빈 화면이 남지 않는다).
- **AC-10** Given 노선도 초기 로드, When 네트워크 요청을 확인하면, Then 카카오맵 SDK 요청이 발생하지 않는다 (지연 로드 검증).
- **AC-11** Given 노선도에서 방문 집계를 이미 받은 상태, When 지도로 전환하면, Then 방문 집계 재요청이 발생하지 않는다.
- **AC-12** Given 지도 보기, When 호선 필터 셀렉트박스를 찾으면, Then 표시되지 않는다.
- **AC-13** Given 커플 A 사용자, When 지도의 핀을 확인하면, Then 커플 B의 방문 역 핀은 나타나지 않는다.
- **AC-14** Given 지도 사용 중, When 네트워크 요청을 감사하면, Then 커플의 방문 좌표를 외부 API로 전송하는 요청이 없다.
- **AC-15** Given 키보드 사용, When Tab으로 이동하면, Then 노선도/지도 토글에 도달하고 조작할 수 있다.
- **AC-16** Given 지도에서 임의로 팬/줌해 전체 핀 bounds를 벗어난 상태, When 노선도로 갔다가 다시 지도로 전환하면, Then 지도가 전체 핀 bounds로 되돌아가지 **않고** 직전 중심·확대 레벨이 복원된다 (F-12 > F-06).
- **AC-17** Given 지도 보기에서 팬/줌한 상태, When 브라우저를 새로고침하면, Then 지도 보기 자체는 유지되지만(F-11) 뷰포트는 F-06의 전체 핀 맞춤으로 초기화된다. **이는 결함이 아니라 F-12에 따른 명세 동작이다.**
- **AC-18** Given 핀이 있는 지도에서 핀이 하나도 보이지 않는 곳(예: 강원 산간)까지 팬한 상태, When "전체 핀 보기"를 누르면, Then 전체 핀이 화면에 들어오도록 뷰포트가 맞춰진다(AC-01과 같은 결과). And 이 버튼은 키보드 포커스로도 실행할 수 있으며 접근 가능한 이름이 "전체 핀 보기"다 (F-17·F-17e·F-17f).
- **AC-19** Given 핀에서 멀리 팬한 뒤 노선도로 갔다가 지도로 돌아와 빈 화면이 복원된 상태(AC-16), When "전체 핀 보기"를 누르면, Then 전체 핀 bounds로 복귀한다. **자동 복귀는 일어나지 않고 이 버튼을 눌러야만 복귀하는 것이 정상 동작이다.**
- **AC-20** Given 기록이 있는 역이 1곳뿐, When "전체 핀 보기"를 누르면, Then 그 핀이 F-06의 단일 핀 배율로 화면 중앙에 온다 (과도하게 확대되지 않는다).
- **AC-21** Given 기록 0건인 빈 상태, When 지도를 보면, Then "전체 핀 보기" 버튼이 표시되지 않는다 (F-17b). And 핀이 1개 이상인 상태에서는 뷰포트가 어디에 있든 항상 표시된다 (F-17a).
- **AC-22** Given "전체 핀 보기"로 리셋한 직후, When 노선도로 갔다가 지도로 돌아오면, Then 리셋된 뷰포트가 복원된다 (F-17c — 리셋 결과도 F-12의 보존 대상).

> ✅ **결정 완료 (2026-08-21) — F-06(초기 bounds 맞춤)과 F-12(뷰포트 복원)의 우선순위**
> 복원할 뷰포트를 가진 채 지도에 재진입하면 두 요구가 동시에 걸린다. **F-12(복원)가 이긴다** —

> 동작하지 않는 것과 같다. 같은 이유로 F-07(기록 0건 기본 뷰)보다도 복원이 우선한다.

> ✅ **결정 완료 (2026-08-25) — 토글 UI의 레이아웃 점프 방지 정책**: 토글의 **시각적 형태
> (세그먼트 컨트롤 vs 아이콘 버튼)는 계속 디자이너 몫으로 남긴다** — 이건 컴포넌트
> 형태 선택이라 `CLAUDE.md` 규약상 planner가 결정할 사안이 아니다. 다만 **기능 요구사항
> 레벨에서 레이아웃 점프를 막는 제약 하나만 이번에 못박는다**: 지도 모드에서 호선 필터가
> 사라질 때(F-13), 헤더 영역은 필터 유무와 무관하게 **같은 높이를 유지**해야 한다(필터
> 요소를 DOM에서 완전히 제거하지 않고 자리만 비우거나, 헤더 컨테이너 높이를 필터 유무와
> 독립적으로 고정하는 두 방법 중 하나 — 구체적 구현은 개발자 몫). 이 제약은 F-13에 종속
> 요구사항으로 추가한다.
>
> **근거**: 노선도 ↔ 지도 토글은 §1이 강조하듯 "같은 데이터의 다른 표현"이라 두 화면이
> 다른 세계처럼 느껴지면 안 되는데, 토글 직후 헤더 높이가 출렁이면(필터 줄 자체가
> 있다가 없어짐) 그 위화감이 가장 먼저 드러나는 지점이 된다. 이건 미감이 아니라
> "전환 시 화면이 흔들리지 않아야 한다"는 기능적 요구라 planner가 정할 수 있는 범위다.

> ✅ **결정 완료 (2026-08-21) — 핀이 보이지 않는 뷰포트의 탈출구: "전체 핀 보기" 버튼을 만든다 (F-17)**
>
> **결정**: 노선도 `03` F-22의 대응물을 지도에도 둔다. **상시 노출**이며, 누르면 F-06의 초기
> 뷰포트 계산(전체 핀 bounds / 핀 1개면 단일 핀 배율)을 그대로 다시 적용한다. 핀 0건일 때만
> 숨긴다. 상세는 F-17 ~ F-17f, 검증은 AC-18 ~ AC-22.
>
> **근거**
> 1. **지도가 노선도보다 더 길을 잃기 쉽다.** 노선도에는 팬 범위 제한(`03` F-19: 노선도 경계
>    + 여백)과 줌 상한(F-18)이 있어서 화면 밖으로 완전히 벗어나기 어려운데도 F-22를 뒀다
>    (`03` F-22 "길을 잃었을 때의 탈출구"). 지도에는 그런 제약이 없다 — 카카오맵은 한반도
>    밖 어디로든 팬된다. 제약이 더 약한 화면에 탈출구가 없는 것은 앞뒤가 맞지 않는다.
>    그래서 우선순위도 `03` F-22의 Should보다 높은 **Must**로 뒀다.
> 2. **두 뷰는 "같은 데이터의 다른 표현"이다(§1).** 토글로 오갔을 때 한쪽에만 있는 조작이
>    있으면 "서로 다른 세계"가 된다. 같은 자리·같은 계열 심볼을 요구한 것(F-17e)도 이 때문이다.
> 3. **F-12 > F-06 결정의 대가를 사용자가 직접 갚을 수 있어야 한다.** 자동 복귀를 하지 않기로
>    한 이상(F-06), 수동 복귀 수단이 없으면 그 결정은 그냥 버그처럼 보인다.
>
> **채택하지 않은 선택지**
> - **(b) 조건부 노출** — "현재 뷰포트가 핀을 하나도 담고 있지 않을 때만 버튼을 띄운다".
>   기각. ① 팬/줌 중 경계에서 버튼이 나타났다 사라져 산만하다. ② 길을 잃은 뒤에야 처음
>   보이는 컨트롤은 사용자가 존재를 학습하지 못한다 — 정작 필요할 때 "원래 없던 게 왜 떴지"가
>   된다. ③ 팬/줌마다 핀 N개의 bounds 포함 여부를 재판정해야 해서 상시 노출보다 비싸다.
>   얻는 것은 "버튼 하나가 안 보이는 것"뿐이다.
> - **(c) 만들지 않는다** — "지도는 팬/줌이 쉬우니 사용자가 알아서 되돌아온다". 기각.
>   축소해서 클러스터를 찾아 다시 확대하는 여러 단계를 사용자에게 떠넘기는 것이고, 무엇보다
>   **복원된 빈 화면은 사용자가 만든 것이 아니라 앱이 복원한 것**이다. 앱이 만든 상태에서
>   빠져나오는 비용을 사용자가 치르게 하면 안 된다.
> - **(d) 자동 복귀**(복원 뷰포트에 핀이 없으면 자동으로 bounds 맞춤) — 기각. F-12 > F-06
>   결정을 조건부로 뒤집는 셈이라 "어떨 때 복원되고 어떨 때 안 되는지"를 사용자가 예측할 수
>   없게 된다. 되돌리는 시점은 사용자가 정한다.

> ✅ **확인 완료 (2026-08-26) — 카카오맵 도메인 등록**: 실 카카오 서버에 `Referer` 헤더를
> 바꿔가며 SDK 요청을 직접 보내 검증했다(콘솔 로그인 불필요 — 도메인 검증은 요청 시점에
> 서버가 응답으로 알려준다). `Referer: http://localhost:5173/`은 SDK가 정상 응답(200) —
> 로컬 개발 도메인은 등록돼 있다. `http://127.0.0.1:5173/`이나 다른 포트는
> `401 {"errorType":"AccessDeniedError","message":"domain mismatched..."}`로 명확히
> 거부됨 — 정확히 `localhost:5173` 하나만 등록된 상태다. **배포 도메인(Vercel)은 아직
> 미배포라 등록 여부 자체가 성립하지 않는다** — 배포 시점에 카카오 개발자 콘솔에서 실제
> 배포 URL을 추가 등록해야 한다(빠뜨리면 F-14 SDK 로드가 조용히 실패하고 §2.2 "노선도로
> 자동 복귀 + 토스트" 경로를 탄다).
