# 개인 공간·기록 탐색 계약

2026-10-19. 사용자의 전체 후속 작업 실행 위임을 근거로 스펙 14의 권장 정책을 적용한다.

## 소유권과 이전

- 기존 기록·사진·태그·작성자·커플 멤버십은 이동·복사·이름 변경하지 않는다.
- `personal_record_spaces(user_id, space_id)`가 개인 소유권의 근거다. `records.author_id`를 공동 기록의 소유자로 재해석하지 않는다.
- 물리적인 `records.couple_id` FK와 사진 경로를 보존하기 위해 개인 공간도 기존 `couples` 격리 컨테이너를 사용한다. 개인 컨테이너에는 커플 멤버십이나 초대를 만들지 않는다. 화면과 세션에는 `kind=personal`을 명시한다.
- `get_record_context`는 로그인한 사용자에게 개인 컨테이너를 한 번 생성하고 기존 공동 공간 ID를 함께 반환한다. 기본 선택은 개인이며, 이 탭에서 명시적으로 선택한 공동 공간만 복원한다.
- 기존 공동 공간은 기존 멤버의 공동 편집 계약을 유지한다. 새 선택 공유 모음의 읽기 전용 계약과 혼동하지 않는다.

## 요청 권한

- 새 클라이언트는 기록·Storage 요청에 `x-record-scope`를 전송한다. 서버는 본인의 개인 공간 또는 현재 활성 공동 멤버십인지 매 요청에서 검증한다.
- 잘못된 UUID·타인의 공간·해제된 공간은 NULL 범위로 처리한다. 유효하지 않은 헤더를 개인/공동 기본값으로 폴백하지 않는다.
- 헤더 없는 이전 클라이언트는 기존 공동 공간만 사용한다. 개인 데이터가 레거시 요청에 자동 노출되지 않는다.
- 기록 RLS·사진/태그 RLS·집계 뷰·저장 RPC·Storage 정책이 같은 범위를 사용한다. 초대·해제 RPC의 기존 `current_couple_id()`는 유지한다.
- 로그아웃·계정/범위 변경에서 헤더·메모리 캐시를 폐기하고 화면을 다시 마운트한다. 초안과 선택 범위는 사용자별 저장소 키로 분리한다.

## 저장과 장소

- D01–D04의 revision·작업 ID·원자적 사진 저장은 그대로 적용한다.
- `place_name`은 선택, 공백만 있으면 NULL, 최대 80 유니코드 문자다. `save_record_v3`가 본문·장소·태그를 같은 트랜잭션에 저장한다. v2는 기존 장소를 변경하지 않는다.
- 새 탭은 저장 직후 상세에만 연속 작성 버튼을 표시한다. 날짜만 이어받고 나머지는 비운다. 허용된 앱 내부 목록 주소와 검색 조건을 수정·저장 사이에 보존한다.
- 방문일의 상한은 한국 날짜의 오늘이다. 기존 미래 행을 자동 수정하지 않기 위해 새 CHECK는 NOT VALID로 설치하고 이후 쓰기부터 검사한다.

## 검색·기간 이동

- 서버 함수 `filtered_records`의 조건을 목록 RPC와 연월 집계 RPC가 공유한다. 모두 호출자 RLS를 적용하는 security invoker다.
- 검색은 역명·장소·일기 부분 문자열(대소문자 무시)이다. `%`·`_`를 와일드카드로 해석하지 않는다. 태그는 정규화 키 정확 일치다.
- 시작일·종료일은 포함 경계다. 역·태그·날짜·검색을 키셋 `(visited_on DESC,id DESC)`과 함께 적용한다. 브라우저로 모든 태그 후보 ID를 가져오지 않는다.
- 페이지는 21개를 읽어 20개만 표시한다. 다음 커서는 표시된 마지막 행이다. 목록 본문은 200자 발췌만 반환한다.
- 연월 이동은 선택 월 말일을 상한으로 이전 기록을 읽는다. 특정 월만 남기는 필터가 아니다. 검색/기간/태그를 바꾸면 점프를 해제한다.
- `q`, `tag`, `start`, `end`, `month`를 URL과 목록 복귀 캐시에 보존한다.

## 복귀·사진·초안

- 탭 복귀·focus·온라인 복구는 조회 화면을 재검증한다. 편집 폼은 자동으로 덮어쓰지 않는다.
- 상세·역 상세·방문 집계·목록은 오래된 응답을 폐기한다. 조회 실패를 방문 0건·사진 0장으로 해석하지 않는다.
- 깨진 사진은 한 로드 주기에서 자동 재서명 한 번만 수행하고 이후 명시적 재시도를 제공한다. 카드 안에는 중첩 버튼을 만들지 않는다.
- 초안은 글·장소·선택 정보만 저장한다. 사진 Blob은 복원하지 않으며 안내한다. 다른 탭의 초안 변경은 현재 입력을 자동 덮지 않고 선택을 요청한다.

## 운영 정리

- 공동 공간 해제 후 기존 30일 보존 계약을 유지한다. 미참조 사진은 7일 유예한다.
- Storage 객체 정리 후보 확정과 사진 참조 삽입은 동일 경로 advisory lock을 사용한다. 확정한 정리 경로는 새 업로드/사진 목록 확정에 재사용하지 않는다.
- 기본 명령은 dry-run이다. `--apply`는 확정 후보만 Storage API로 삭제하고 결과를 기록한다. 실패는 다음 실행에서 재시도한다.
- Storage 객체가 남아 있으면 만료 공간의 DB 행을 삭제하지 않는다. SQL의 Storage 메타데이터 삭제를 실제 파일 삭제로 대신하지 않는다.
- `PHOTO_CLEANUP_ENABLED=true`와 서버 전용 저장소 비밀 값이 설정된 운영 환경에서만 예약 작업을 실행한다. 로컬 코드 존재를 실제 운영 잡 활성화로 보고하지 않는다.
