## 2. 우선 확인된 핵심 문제

### 2.1 노선도 역 이름이 현재 화면 폭에서 표시 기준에 도달하지 못함

`LineMapCanvas.tsx:21`의 라벨 표시 기준은 실제 화면 배율 0.85이고, 최대 줌은 8이다. 실제 좌표 파일의 폭은 8,217.6, 높이는 7,686.4다. 배율은 `min(화면 폭 / 좌표 폭, 화면 높이 / 좌표 높이) × 줌`으로 결정된다.

| 캔버스 폭 | 8배 확대 시 화면 배율의 상한 | 라벨 표시 기준 | 판정 |
|---|---:|---:|---|
| 360px | 0.3505 | 0.85 | 도달 불가 |
| 390px | 0.3797 | 0.85 | 도달 불가 |
| 480px | 0.4673 | 0.85 | 도달 불가 |
| 767px | 0.7467 | 0.85 | 도달 불가 |

현재 데스크톱 앱 프레임도 480px이다. **현행 기본 레이아웃에서는 최대 확대해도 역 이름과 방문 횟수 배지가 표시되지 않는 구조**다. 390px에서는 약 17.91배가 되어야 기준에 도달한다. 높이가 제한되면 더 큰 배율이 필요하다.

단순히 표시 기준을 낮추면 13단위 글자가 약 5px로 보이는 문제가 남는다. 화면 픽셀 기준 글자·심볼 크기, 줌 상한, 초기 표시 영역을 함께 조정해야 한다. 이 결과는 브라우저 스크린샷 판정이 아니라 **실제 좌표와 렌더 수식 계산 결과**다.

### 2.2 저장·편집 실패가 기존 데이터를 바꿀 수 있음

- 수정 화면은 태그·사진을 별도로 조회하지만, 본문 조회 오류만 확인하고 태그·사진 오류는 빈 배열로 처리한다. 태그 조회만 실패한 상태에서 저장하면 서버가 기존 태그를 빈 목록으로 교체할 수 있다.
- 사진 순서 변경은 기존 메타데이터 DELETE와 INSERT가 별도 요청이다. INSERT가 실패하면 기존 사진 정보가 빠진 상태가 남을 수 있다. 원본 Storage 파일의 즉시 소실과는 구별해야 한다.
- 사진 준비 상태는 `PhotoField` 내부에만 있다. 부모의 저장 가능 여부에는 반영되지 않아 인코딩 중 저장할 수 있다. 준비 완료 전의 사진 목록으로 저장되거나, 처리 도중 사용자가 바꾼 사진 목록을 오래된 배열이 덮을 위험이 있다.
- 공동 수정에는 기존 버전 비교가 없다. ‘사진 다시 올리기’도 본문 저장 RPC부터 다시 호출하므로, 재시도 사이에 다른 기기가 수정한 내용을 덮을 수 있다.

### 2.3 일부 최근 개선은 이미 적용됨

다음은 새 미구현 항목으로 다시 집계하지 않았다.

- 목록 카드에서 감정·날씨·태그의 기본 노출 축소, 정사각형 사진 썸네일.
- 작성 화면의 역 → 날짜 → 사진 → 일기 순서와 접힌 선택 항목.
- 타임라인 태그 필터 접기.
- 타임라인 필터의 이전 요청 응답 차단과 완료 상태에 한정한 캐시 저장.
- 사진 저장 실패 후 이탈 경고 유지.
- 일기 길이 오류 안내를 1,000자로 통일.

사진 실패 이탈 경고가 있다고 해서 사진 DB 변경까지 원자적으로 처리되는 것은 아니다. 타임라인에 적용된 요청 보호도 역 상세·방문 집계에는 같은 수준으로 적용되어 있지 않다.

소셜 피드·공개 랭킹·보상형 연속 기록·자동 GPS 추적·대규모 AI 추천은 이번 우선 범위에 넣지 않는다. 핵심 기록 흐름 개선과 연결되지 않는 기능 확대를 줄이기 위한 제안이다.

### 권장 실행 순서

1. **노선도 메인 개선 — 현재 방향 승인, 기준 유지**: M01–M08, F02 중 반영된 노선도 탐색·작성 진입은 유지한다. 이번 후속 작업에서 노선도 배치를 다시 만들지 않는다. 남은 시각 보정은 별도 백로그로 보존하며 [구현 보고](design/line-map-implementation-2026-10-06.md)에 명시한다.
2. **저장 신뢰성**: R01·R02·R03·R04. 기존 기록 보존, 원자적 저장, 충돌·사진 준비 경합을 점검한다. 이 문서는 별도 작업 트리의 기록 수정 완료 여부를 대신 판정하지 않는다.
3. **제품 계약·복구**: F01·E01·R09, F03·F04, R07·R08. 개인 기본 사용·공동 기록 보존·권한·복구를 정리한다.
4. **작성 편의·화면 정리**: F02의 개인용 문구, F05·F06, R05·R06. 노선도 메인 방향을 유지하며 반복 입력과 이동 횟수를 줄인다.
5. **누적 사용 기능**: F07·X01–X05. 선택 공유·찜·사진 편의·백업·복구를 사용 패턴에 맞춰 순차적으로 추가한다.

E02는 각 단계의 완료 조건에 포함하고, E03은 검색 개발과 함께 처리한다. E04는 관련 코드를 수정하는 단계에 맞춰 진행한다.

### 구현 전에 필요한 제품 결정

- 기존 공동 기록을 공동 공간에 보존할지, 명시적 개인 복사본을 제공할지. 최초 작성자를 일방적으로 개인 소유자로 간주하지 않는다.
- 선택 공유를 읽기 전용으로 시작할지, 참가자의 본인 기록 추가·수정까지 포함할지.
- 장소를 계속 역 중심으로 유지하면서 이름만 추가할지, 실제 장소 좌표까지 확장할지.
- 개별 삭제의 복구 기간, 계정 탈퇴 시 공유 기록 처리, 내보내기 범위.

이 결정들은 분석을 막는 확인 요청이 아니라 해당 기능을 구현할 때 필요한 선행 조건이다.

## 9. 이번 검증과 한계

- 현재 로컬 작업 트리에는 검토 전부터 수정·staging된 앱 파일과 미추적 문서/테스트가 있었다. 분석 기준에 포함했으며 변경하거나 되돌리지 않았다.
- `tsc -p tsconfig.app.json --noEmit`: 성공.
- `tsc -p tsconfig.node.json --noEmit`: 성공.
- `npm run lint`: 오류 없이 완료, 경고 5개. 버튼 모듈의 Fast Refresh 경고 1개와 훅 의존성 경고 4개다.
- `npm run test:db`: **178/178 성공**. PGlite 인메모리 검사로 실서비스 데이터를 변경하지 않았다.
- 실제 좌표 파일을 읽어 646역·33노선, 라벨 배율 조건, 역 원 겹침 11쌍을 계산했다. 환승역의 대표 노선과 다른 소속 노선도 확인했다.
- 브라우저 실렌더, 모바일 실기기, 실제 Supabase Auth/Storage, 실제 카카오맵, 운영 정리 잡, 60fps 성능 측정은 이번 검토에서 수행하지 않았다. 관련 항목을 실환경에서 재현 완료한 결함으로 단정하지 않는다.
- 기존 문서에 적힌 과거 빌드·브라우저 결과를 이번 실행 결과로 재사용하지 않았다. 신규 테스트 코드나 앱 코드를 작성하지 않았다.
- 위 타입·lint·DB 테스트는 최초 백로그 분석 시 실행 결과다. 후속 노선도 문서 개정에서는 이를 다시 실행하지 않았다. 외부 공식 자료와 카카오맵·네이버 도움말 이미지는 별도로 확인했으며, 이를 현재 앱의 브라우저 테스트로 간주하지 않는다.
