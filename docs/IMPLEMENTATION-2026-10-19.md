## 검증

- DB: 276개(현재 스키마 203, 전환 전 계약 이력 73) 통과. 동일 날짜/태그 기록 1,050건의 페이지 누락·중복, 검색 경계, 개인/공동 범위 분리·파트너 개인 사진 업로드 거부와 정리 작업의 권한/참조 보호 포함.
- 브라우저: 기존 실패·복구 17개와 실제 상세/세션/검색/재연결/연속 작성 6개 시나리오 통과. 외부 요청은 전부 모킹한다.
- 목업: 1440px/390px, 검색·역 선택·작성 폼, 런타임 오류/가로 넘침 없음 확인.
- 타입·프로덕션 빌드 통과. lint 오류 0, 기존 UI 버튼 Fast Refresh 경고 1. 노선도 정합성/재생성 검사와 회귀 8개 통과.

## 운영 적용 상태

- 기존 Supabase 호스트는 일반/확장 실행 환경 모두 DNS ENOTFOUND였다. 프로젝트가 삭제/중지됐다고 단정하지 않는다.
- 관리 API/DB 연결 정보와 Supabase·Vercel 연결이 확인되지 않았다. 실제 Auth·Storage·동시 DB 세션, 마이그레이션·예약 활성화·배포는 수행하지 않았다.
- 적용 순서는 테스트 프로젝트에 10월 15일 저장 계약 → 10월 19일 개인 공간 → 검색/장소 → 정리 작업 마이그레이션, 실제 권한/Storage 회귀, 새 클라이언트 배포다. 구 쓰기를 차단하는 전환이므로 기존 탭의 초안 보존·새로고침 안내를 점검한다.
- `npm run service:inspect`는 RPC 존재/만료 공간 수만 조회한다. `npm run photos:cleanup`은 기본 dry-run이다. 실제 삭제는 연결된 테스트 환경에서 검증한 후 운영 스케줄로 활성화한다.
- 의존성 점검에서 기존 Tailwind 3의 개발 도구 취약점이 남아 있다. 호환 범위의 source-map-js 패치는 적용했다. 강제 Tailwind 4 전환은 하지 않았다.
