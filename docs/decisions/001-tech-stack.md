# 001 — 기술 스택 확정

## 배경

노션 PRD §8은 실 서비스 전환 시 기술 스택이 미정임을 명시했다. 프로토타입은 React 기반 단일
HTML(목데이터, 백엔드 없음)로만 존재했다.

## 선택지

- **프레임워크**: Next.js(App Router) vs Vite+React(SPA)
- **백엔드**: Supabase vs Firebase vs 직접 구축
- **지도 API**: 카카오맵 vs Google Maps vs 네이버지도
- **노선도 렌더링**: 직접 그린 SVG vs 지도 API 오버레이 vs 오픈소스 노선도 라이브러리
- **커플 연결**: 초대 코드 vs 소셜 로그인 연동

## 결정 (2026-08-11, 사용자와 함께 확정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 프레임워크 | Vite + React + TypeScript (SPA) | 서버 컴포넌트/라우트가 필요 없는 규모. Supabase를 클라이언트에서 직접 호출하면 충분하고, 기존 프로토타입(React)과 결이 가장 가까움 |
| 백엔드 | Supabase (Postgres+Auth+Storage) | 계정·사진 저장·기록 CRUD를 한 서비스로 해결, 별도 서버 운영 불필요 |
| 노선도 | 직접 그린 SVG + 좌표 데이터 | 노선도 특유의 도식화(실제 지리와 다른 배치)는 지도 API로 표현 불가. 지도 API 비용·쿼터 없이 완전한 스타일 커스터마이징 가능 |
| 지도 보기(보조) | 카카오맵 | 국내 사용자 대상 서비스 특성상 UX·데이터 품질이 국내 지도 서비스가 유리 |
| 역 좌표 데이터 | 전국도시철도역사정보표준데이터 (공공데이터포털 파일데이터) | 실 위경도·역명·호선 데이터를 공식 소스에서 확보. TAGO API는 실 호출 검증 실패로 폐기(아래 트레이드오프 참고) |
| 커플 연결 | 초대 코드 | 소셜 로그인 연동/심사 부담 없이 이메일+비밀번호와 코드만으로 MVP 구현 가능 |
| 배포 | Vercel | Vite 정적 빌드 배포에 적합, 무료 티어로 충분 |

## 트레이드오프

- Next.js를 쓰지 않으므로 서버 사이드 렌더링/SEO 이점은 없다 — 로그인 기반 개인 기록 서비스라
  검색 노출이 중요하지 않아 수용 가능한 트레이드오프로 판단.
- TAGO API는 과거(별개 프로젝트 기준 2026-08-03) 키 미승인 이슈가 있었다. 2026-08-12에
  실제 키로 처음 실 호출을 시도했으나, 예상했던 "키 미승인" 에러가 아니라
  `NO_OPENAPI_SERVICE_ERROR`(요청 URL이 게이트웨이에 등록된 서비스와 매칭 안 됨)가
  나왔다 — 코드에 박힌 엔드포인트 URL 자체가 더 이상 유효하지 않은 것으로 진단됨
  (`docs/specs/02-station-master.md` §9 상세 기록). 엔드포인트를 다시 찾는 대신
  **전국도시철도역사정보표준데이터로 확정**했다(2026-08-12, 사용자 결정). TAGO 어댑터
  코드(`scripts/station-master/sources/tago.mjs`)는 남겨두되 기본 경로에서 제외한다.
- 안 가본 역 추천의 전국 단위 확장은 미결정으로 남겨둠 — MVP는 수도권 주요 노선으로 축소.
