# 003 — 노선도 도식 좌표를 DB가 아닌 정적 자산으로 관리

## 배경

노선도는 이 서비스의 기본 화면이자 정체성이다(`docs/specs/03-line-map.md`).
그런데 노선도에는 **두 종류의 좌표**가 있다.

| 종류 | 예 | 성격 |
|---|---|---|
| 지리 좌표 (위경도) | 홍대입구 37.5568, 126.9237 | 사실 데이터. 공공데이터에서 온다 |
| 도식 좌표 (SVG x/y) | 홍대입구 (412, 288) | **저작물.** 가독성을 위해 지리를 왜곡한 결과 |

실제 지하철 노선도는 지리적으로 부정확하다. 선을 45도 배수로 꺾고, 밀집 구간을 늘리고,
외곽을 압축한다. 위경도를 그대로 그리면 노선도가 아니라 그냥 점 지도가 된다.

따라서 도식 좌표는 `02-station-master.md`의 마스터 적재 배치가 만들 수 없는 데이터이며,
**어디에 저장하고 누가 소유할 것인지**를 따로 정해야 했다.

## 선택지

### A. DB 테이블(`station_map_positions`)에 저장
- 역 마스터와 같은 곳에서 관리되어 일관돼 보인다
- 노선도 첫 렌더에 DB 왕복이 하나 더 붙는다
- 좌표를 고치려면 SQL을 실행해야 한다. **손으로 다듬는 작업**인데 diff·리뷰·롤백이 어렵다
- 마스터 재적재 배치가 실수로 덮어쓸 위험이 상존한다

### B. 리포지토리의 정적 데이터 파일
- 코드와 함께 버전 관리된다. PR에서 좌표 변경을 리뷰하고 되돌릴 수 있다
- 정적 자산이라 CDN에서 오고, DB 왕복이 없다
- DB의 역 마스터와 **어긋날 수 있다** (신규 개통역이 좌표 파일에 없는 경우)

### C. 위경도에서 자동 생성 (격자 스냅 + 알고리즘)
- 수작업 0
- 실제 노선도 품질이 나오지 않는다. 밀집 구간이 뭉치고 라벨이 겹친다
- PRD §5.1의 "실제 노선도 형태처럼"을 만족하지 못한다

## 결정 (2026-08-11)

**B를 채택한다.** 노선도 도식 좌표와 노선 폴리라인은 리포지토리의 정적 데이터 파일로
관리하며, DB에 저장하지 않는다.

1. 파일은 `viewBox`, 노선별 `polyline`, 역별 `{x, y, labelAnchor}`를 담는다.
   논리적 shape는 `docs/specs/03-line-map.md` §4.2가 정본이다.
2. **DB와의 조인 키는 `stations.code` / `lines.code`라는 문자열 자연키**다.
   uuid를 쓰지 않는다 — uuid는 사람이 파일을 편집할 수 없게 만들고, 환경마다 값이 다르다.
3. 정합성은 **CI 검증 스크립트**로 지킨다.
   - 정적 파일의 `stationCode`/`lineCode`가 DB에 없으면 → **실패**
   - DB의 MVP 범위 역 중 정적 파일에 없는 것이 있으면 → **경고**
     (신규 개통역이 좌표 작업 전이라는 이유로 배포를 막으면 안 된다)
4. 좌표가 없는 역은 노선도에 그리지 않는다. 대신 화면에 "노선도에 아직 표시되지 않은
   역 N개"를 노출해 기록이 사라져 보이지 않게 한다 (`03-line-map.md` §2.2).
5. 파일 단위는 **권역**으로 잡는다. 지금은 수도권 1개 파일이며 분할하지 않는다.

## 트레이드오프

**얻은 것**
- 노선도 첫 렌더에 DB 왕복이 없다. 기본 화면의 초기 로드 예산(2.5초)에 직접 기여한다.
- 좌표 조정이 코드 리뷰 대상이 된다. 노선도 미세 조정은 반복 작업이라 이게 크다.
- 마스터 적재 배치가 도식을 건드릴 수 없다 — 책임 경계가 물리적으로 분리된다.

**포기한 것**
- 런타임 수정 불가. 좌표를 고치려면 재배포해야 한다. (운영 중 노선도를 급히 고쳐야 할
  시나리오는 없다고 판단했다.)
- DB와 파일이라는 **두 곳에 데이터가 나뉜다.** CI 검증이 이 비용을 감당한다.
  검증을 만들지 않으면 이 결정은 나쁜 결정이 된다.

**되돌리기**
- B → A로의 이전은 쉽다 (파일 내용을 테이블에 넣으면 된다).
- 되돌리기 어려운 쪽은 **조인 키를 `code`로 정한 것**이다. 파일과 DB, 그리고 향후 노선도
  저작 도구가 모두 이 키에 의존하게 된다. `stations.code`의 안정성
  (`02-station-master.md` F-06: 그룹 내 최소 역번호 기반)이 깨지면 노선도 전체가 어긋난다.

## 남은 리스크

**도식 좌표를 누가 만드는가가 정해지지 않았다.** 수도권 700역의 좌표를 찍는 것은 이 결정이
해결해주지 않는 별개의 작업량이며, `03-line-map.md` §9의 최대 미결정 항목이다.
후보는 (a) 위경도 자동 배치 후 수작업 보정, (b) 공개 노선도 도식 데이터 변환,
(c) MVP 범위를 1~9호선(약 300역)으로 축소. **이 결정 없이는 기본 화면을 완성할 수 없다.**
