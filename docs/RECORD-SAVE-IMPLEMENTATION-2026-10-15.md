# D01–D04 저장 신뢰성 구현 보고

작성일: 2026-10-15  
상태: **로컬 구현·검증 완료. 운영 DB 마이그레이션·프론트 배포·push 미수행. 변경은 미커밋.**

## 사용자에게 달라지는 동작

| 작업 | 구현 |
|---|---|
| D01 완전한 수정 로드 | 본문·태그·사진·버전을 한 스냅샷 RPC로 읽는다. 실패하면 저장 폼을 열지 않는다. 서명 URL만 실패하면 사진 개수·순서를 유지한다. 계정·공간·기록 변경 시 편집기를 분리하고 이전 응답을 폐기한다 |
| D02 사진 준비 경합 | 준비 즉시 부모의 저장과 이탈 보호에 반영한다. 글 입력은 허용하고 저장·사진 목록 조작은 잠근다. 파일 일부 디코딩 실패 시 나머지 사진을 보존하고 화면 종료 후 완료를 폐기한다 |
| D03 저장 서버 계약 | 본문/태그와 사진 목록 모두 동일 기록 revision을 검사한다. 사진 목록 교체는 한 트랜잭션이다. 성공 영수증으로 같은 요청의 재시도를 확인하고 다른 내용의 작업 ID 재사용을 거부한다 |
| D04 입력·결과 복구 | 신규 기록 ID를 먼저 고정한다. 사용자/공간/경로별로 불변 요청과 사진 편집 목록을 보관한다. 본문 성공 뒤 사진 단계에서도 복구 기준을 유지한다. 사진만 재시도할 때 본문을 전송하지 않는다. 충돌은 비교 후 사용자 선택으로 재적용한다 |

사진 일부 업로드 실패 시 **기존 DB 사진 목록 전체를 유지**한다. 이미 업로드한 새 파일은 메모리에 기억해 실패한 파일만 다시 올린다. 본문은 이미 저장되었음을 별도로 안내한다.

새로고침 후 같은 작업 결과를 확인하며 신규 기록을 중복 생성하지 않는다. 사진 Blob은 저장하지 않는다. 사진 파일이 없어졌다면 재선택하거나 명시적으로 새 사진을 제외한다. 미확인 요청 또는 복원할 초안이 있는 동안 자동 저장이 더 최신 초안을 덮지 않는다.

DB 러너는 `30-records`·`60-upsert-record`만 전환 전 권한으로 검사한 뒤 실제 새 마이그레이션을 적용한다. 나머지 기존 검사와 새 쓰기 검사는 현재 권한에서 실행한다. 회수한 권한을 테스트 편의를 위해 다시 부여하지 않는다.

브라우저 명령은 Playwright 준비가 필요하다. 번들 모듈을 쓸 때는 `PLAYWRIGHT_MODULE`을 해당 경로로 지정한다. `npm run test:browser`는 기본 `127.0.0.1:5175`에서 Vite를 실행하고 종료 시 정리한다. 이미 실행한 서버를 쓸 때는 `TEST_BASE_URL`을 지정하고 `node tests/browser/run.mjs`를 실행한다.

## 운영 적용과 남은 검증

1. 테스트 Supabase에서 새 마이그레이션을 적용하고 실제 Auth·PostgREST 오류 봉투·Storage 업로드/서명/삭제와 복수 세션 경합을 검증한다. PGlite와 모킹 브라우저는 이를 대체하지 않는다.
2. 이 마이그레이션은 구 `upsert_record` 및 직접 테이블 쓰기를 차단한다. 운영 전환 시간을 정하고 구 탭의 입력 보존과 새로고침 안내를 확인해야 한다.
3. 서버 계약 적용 후 새 클라이언트를 배포한다. 새 RPC 미존재 시 구 DELETE/INSERT 또는 무조건 덮어쓰기 경로로 폴백하지 않는다.
4. DB와 Storage 바이너리까지 하나의 트랜잭션이라는 보장은 없다. 미참조 업로드·객체 정리 실패 및 영수증 보존/정리는 D07의 별도 운영 작업이다. 현재 영수증은 자동 만료시키지 않고 생성 ID 묘비도 유지한다.
5. 실제 동시 연결의 잠금 스케줄링·모바일 실기기 동작·성능 목표는 미검증이다. DB 테스트는 동일 기준 버전의 순차 요청으로 충돌을 재현한다.

노선도 개선과 기존 미커밋 UI 작업을 보존했다. 기존 공동 공간 권한과 개인 전환 정책은 이번 구현에서 바꾸지 않았다. 다음 제품 결정은 D05의 기존 공동 기록 보존/복사 방식과 선택 공유 권한이다.
